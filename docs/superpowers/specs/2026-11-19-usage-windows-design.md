# 取得先が返す使用枠をすべて表示する（2026年10〜11月の仕様変更への対応）

## 問題

アプリは「Claudeは5時間と週の2枠、Codex・Grokは週の1枠」と決め打ちしている。各社の仕様が変わり、この前提が合わなくなった。

### Claude（Anthropicのヘルプセンターと料金ページで確認）

- Max 20xは **Ultra** に名前が変わった。既存のMax 20x契約は、同じ料金で自動的にUltraへ移った。$100のプランは、表記が単に **Max** になった（以前は「Max 5x」と表示）。
- **Pro**：5時間の制限と、週の制限がある。Fableは使用クレジットで支払う。Fable専用の週の制限は書かれていない。
- **Max**：5時間の制限、全モデル共通の週の制限、**Fable専用の週の制限**がある。
- **Ultra**：認証済みのアカウントには **5時間の制限がない**。全モデル共通の週の制限と、Fable専用の週の制限がある。認証前は一時的な制限がかかり、設定画面では「Current session」の行として表示される。
- 内部の契約名は今も `max_20x` が使われている（料金ページのリンクに残っている）。
- 使用量の取得先 `api/oauth/usage` は、公開されていない仕様。開発者の報告（GitHub、2026年7〜11月）によると、応答に `limits` という配列が加わった。
  - 配列の各項目は `kind`、`group`、`percent`、`severity`、`resets_at`、`scope` を持つ。
  - `kind` の値は、`session`（5時間）、`weekly_all`（週・全モデル）、`weekly_scoped`（週・特定のモデル）。`weekly_scoped` では、モデル名が `scope.model.display_name`（例 `Fable`）に入る。
  - 従来の `five_hour` と `seven_day` も残っている。モデル別の `seven_day_opus` と `seven_day_sonnet` は、常に null になった。
- 認証済みのUltraのアカウントでは、表示データの5時間枠が、割合もリセット時刻も null になる。週の値は取れる（以前のアプリの表示は「Max 20x」）。

### Codex（OpenAIの料金ページと、OpenAI開発者フォーラムでのOpenAIの回答で確認）

- **Pro系のプランには5時間の制限がない**。週の制限だけ。Pro系のアカウントでは、記録にも週の枠しかない。
- **Plusには5時間の制限がある**。7月に一時的になくなり、その後戻った。Businessの上位プランには5時間の制限がない。
- アプリは週の枠（`limit_window_seconds = 604800`、記録では `window_minutes = 10080`）しか読まず、Plusの5時間の枠を表示できない。
- 「12月からChatGPTとCodexの枠が共通になる」という記事があるが、OpenAIの公式な発表は確認できていない。

### Grok（xAIの公式文書で確認）

- 有料の契約ごとに、週の枠が1つある。この枠をGrokの各製品とCursorが共有し、**Grok Botも同じ枠を使う**（Premium以上）。
- 契約名はPlus・Premium・Super・Ultra。SuperGrokは新規の受付が終わった。
- アプリの取得方法は変えなくてよい。ただし文書の「Grok Botの別枠は取得しません」は、もう正しくない。

## 目的

各サービスが返した使用枠を、決め打ちせずにすべて表示する。プランによって枠の数が違っても、それぞれの利用者に本当の制限が見えるようにする。

## 利用者が決めたこと

- A案：「取得先が返す枠をすべて表示する」を採用する。
- これまでに決めたことは変えない：問い合わせはトレイアプリ1か所だけ。「未取得」と0%を区別する。古い値を新しい値として見せない。

## 目標

- Claudeの枠：
  - `limits` 配列から作る。`session` は「5時間」、`weekly_all` は「週」、`weekly_scoped` は「週（モデル名）」（例「週（Fable）」）。
  - 配列がない、または有効な項目が1つもないときは、従来の `five_hour` と `seven_day` から作る。`usage-cache.json` も同じ方法で読む。
- Codexの枠：オンライン応答の `primary_window` と `secondary_window` から作る。18000秒は「5時間」、604800秒は「週」。セッションの記録でも同じく、300分は「5時間」、10080分は「週」として読む。
- Grokの枠：「週」のまま。
- 返ってこなかった枠は表示しない。枠が1つもないサービスは、サービス全体を「未取得」と表示する。割合だけが null で、リセット時刻などがある枠は、従来どおり「未取得」と表示する。
- 枠の並び順：5時間、週、週（モデル名）。1つのサービスで表示する枠は最大4つ。
- Claudeのプラン名：`max` で `20x` を含むものは「Ultra」、`5x` を含むものと `max` だけのものは「Max」と表示する。`ultra` はこれまでどおり「Ultra」。
- 警告と予測：枠ごとに判定する。5時間の規則と週の規則は、枠の名前ではなく枠の長さで選ぶ。「週（Fable）」は週の規則を使う。
- 予測の履歴：
  - 新しい枠（「Claude/週（Fable）」「Codex/5時間」など）も学習する。
  - 「Max 20x」から「Ultra」、「Max 5x」から「Max」への名前の変更は、プランの変更として扱わない。これまでの学習を続ける。
- 表示する場所すべてを、枠の数が変わっても正しく表示できるようにする：トレイの一覧（`src/PopupForm.cs`）、Windowsウィジェット（`src/WidgetCards.cs`）、Obsidianのツールバー（`obsidian/src/`）、Stream Deckのキー（`streamdeck/src/`）。

## 対象外

- ChatGPTとCodexの枠が共通になるという話への対応（公式の発表がないため）。
- 追加の使用クレジット：Claudeの `extra_usage`、Codexのクレジット、Grokの追加クレジット。
- 取得先が返す `severity`。警告はアプリの規則で判定し続ける。
- 中身が常に null になったモデル別の `seven_day_opus` と `seven_day_sonnet`。
- 問い合わせの頻度や取得先を変えること。

## 失敗とみなすこと

- 5時間の制限があるプラン（Pro、Max、認証前のUltra、Codex Plus）で、5時間の枠が表示されない。
- MaxやUltraで、Fableの週の枠が表示されない。
- 5時間の制限がないプランで、「5時間 未取得」が出る。
- 未取得を0%と表示する。古い値を新しい値と同じ見た目で表示する。
- 5時間の枠に週の予測規則を使う、またはその逆。
- プラン名の変更だけで、これまでの学習を捨てる。既存の「Claude/週」の履歴が途切れる。
- 取得先が知らない `kind` や壊れた項目を返したとき、ほかの枠まで表示できなくなる。
- 取得先が返したモデル名（外部の文字列）が、長すぎたり制御文字を含んだりして、表示や保存を壊す。

## 制約

- トレイアプリは.NET Framework 4.8と、C# 5の文法で書く。npmの依存パッケージは入れない（`build.ps1`、`node --test`、CI `.github/workflows/build.yml`）。
- 取得先は公開されていない仕様。項目の欠け、型の違い、知らない値があっても動くように読む。応答のサイズ上限（1 MiB）はこれまでどおり。
- 取得先が返したモデル名は、英数字・空白・`.`・`+`・`-`・`(`・`)` だけを残して整える。連続する空白はまとめ、24文字で切る。整えた結果が空なら「週（モデル別）」と表示する。どの場合も、枠そのものは捨てない（設計者の判断。表示名が少し変わっただけで枠が消えないようにするため）。
- 表示データ（名前付きパイプ）は64 KiB以下。Obsidianプラグインとストリームデッキプラグインは、同じソース版で作る前提（今の文書のとおり）。
- 実データ（利用者の割合や時刻）をテストや文書に入れない。

## 検討した方法

| 案 | 内容 | 長所 | 短所 | 判断 |
|---|---|---|---|---|
| **A** | 各サービスが返した枠をすべて表示する。表示データの形を変え、表示する場所すべてを更新する | 各プランの本当の制限が見える。仕様がまた変わっても追いつきやすい | 変更が広い（トレイ・ウィジェット・Obsidian・Stream Deck） | **採用** |
| B | 返ってこない5時間の枠を隠し、Ultraの名前と文書だけ直す | 小さく早い | Fableの週の枠と、Codex Plusの5時間の枠が見えないまま | 不採用 |
| A' | 表示データの形は変えず、枠の欄を固定で増やす | 既存の受け手を少し直すだけで済む | 受け手が枠の名前を決め打ちしたまま。仕様が変わるたびに直す必要がある | 不採用 |

## 設計

### データの形（`src/Models.cs`）

- `UsageWindow` に、枠の長さ `Span`（5時間／週）を加える。モデル別の週の枠には、モデル名 `Scope` を持たせる。
- 表示名 `Label`（「5時間」「週」「週（Fable）」）と、狭い場所向けの短い名前（「5h」「週」「Fable」）は、`Span` と `Scope` から作る。
- `ServiceUsage.Empty` は枠を作らない。枠は解析した結果だけから作る。

### 解析（`src/Parsers.cs`、`src/Providers.cs`）

- Claude（オンライン・保存値の両方）：
  - まず `limits` 配列から枠を作る。各項目は `percent`（なければ `utilization`）と `resets_at` を読む。
  - `limits` に「5時間」または「週」の枠がなく、従来の `five_hour` または `seven_day` に有効な割合があるときは、その枠を従来の項目で補う（設計者の判断。取得先が従来の項目で5時間の値を返しているなら、5時間の制限はかかっていると考える。Ultraの実データでは `five_hour` は null）。
  - 知らない `kind` と、`percent` が不正な項目は読み飛ばす。`group` は使わない。
  - 同じ枠（同じ `kind` で、`weekly_scoped` なら同じモデル名）が2つ以上あるときは、割合の高いほうを使う（設計者の判断。低いほうを見せて警告が遅れるのを避けるため）。
  - 枠が1つもない応答は「使用量を取得できません」とし、従来どおり保存値で補う。
- Codex：オンライン・記録とも、5時間と週の両方を読む。週の枠がなくても、5時間の枠だけで取得成功とする。コードレビュー用などの別枠は、これまでどおり混ぜない。
- Grok：変更なし（`ServiceUsage.Empty` の変更に合わせるだけ）。

### 警告・予測（`src/Alerts.cs`、`src/Forecast.cs`、`src/Pace.cs`、`src/ForecastHistory.cs`）

- `window.Label == "週"` で判定している所を、`Span` で判定するように変える。
- 履歴の鍵は「サービス名/表示名」のまま。そのため「Claude/週」「Claude/5時間」の既存の履歴は続く。
- 受け付ける鍵の一覧は、「3サービス × 5時間・週・週（モデル名）」に広げる。モデル名は上の制約に合うものだけ。
- 既知のプラン名に「Ultra」と「Max」を加える。履歴を読み込むとき、「Max 20x」を「Ultra」、「Max 5x」を「Max」に置き換える。これで名前の変更だけでは学習が区切られない。
- 履歴は新しいファイル `%LOCALAPPDATA%\AIUsageManager\forecast-history-2.dat` に保存する（設計者の判断）。
  - 新しいファイルがないときは、今の `forecast-history.dat` を読んで引き継ぐ。今のファイルには書き込まない。
  - 理由：今のビルドは、知らない鍵や5つ以上の系列を含む履歴ファイルを、まるごと捨てて上書きする。保存先は全ビルド共通なので、確認の途中で以前のビルドを起動すると、「Claude/週」の学習まで消えてしまう。
  - 履歴の削除（トレイの「学習履歴を削除」）は、両方のファイルを消す。

### 表示データ（`src/Snapshot.cs`、schemaVersion 2）

- サービスごとの `windows` を0〜4個の可変にする。
- 各枠には `label`、`shortLabel`、`span`（`"5h"`／`"week"`）、`percent`、`resetsAt`、`pace`、`alert` を入れる。
- 受け手（`obsidian/src/usage.js` の `parseSnapshot`、Stream Deckも同じものを使う）は、schemaVersion 2 だけを受け付ける。枠の数・名前・`span` の形を検証する。
- schemaVersion 1 の旧版とは混在させない（設計者の判断。版ごとに出し分ける仕組みは作らない）。旧版と新版を組み合わせたときは、今のコードのまま次のように表示される。これを文書に書く。
  - Obsidian：「連携できません · 設定を確認」
  - Stream Deck：2回続けて読めなかった後に「未接続」
  - 対処は、トレイアプリとプラグインを同じソース版でビルドし直すこと。

### 表示

- トレイの一覧：枠の数に合わせて列を分ける（1〜4）。名前の欄が狭い場合は短い名前を使う。枠が0個なら「未取得」と表示する。
- ウィジェット：枠の数に合わせて列とバーの幅を決める。
- Obsidian：枠の数が変わったら、その行の枠の表示を作り直す。縮小表示では短い名前を使う。
- Stream Deck：1つのキーに最大3本まで描く（Claude Maxの5時間・週・Fable）。4つ目以降は描かない。3本のときの配置は、縦・横・リングの各表示で読める大きさにする。返ってこなかった枠は、今の版と同じく描かない。

### 実データでの確認の結果（2026-11-19）

- Claude（Ultraのアカウント。内部名は `max` / `default_claude_max_20x`）：
  - `five_hour` は null。`seven_day` は `utilization`（0〜100の整数）と `resets_at`（小数秒付きのISO日時）を持つ。
  - `limits` は応答の最上位にある。項目は `weekly_all`（`scope` は null）と `weekly_scoped`（`scope.model.display_name` は "Fable"）の2つ。各項目は `kind`、`group`、`percent`（0〜100の整数）、`severity`、`resets_at`（ISO日時）、`scope`、`is_active` を持つ。
  - `session` の項目はない。GitHubの報告と同じ形。
- `is_active` は使わない（設計者の判断）。意味が公開されておらず、実際に効いているFableの枠が `false` になる例が報告されているため。
- 応答にはほかにも `extra_usage`、`spend`、`seven_day_breakdown`（Claude Code・チャットなど用途別の内訳）、`weekly_scoped_shares`、名前の意味が分からない多数の項目（すべて null）がある。今回はどれも使わない。
- Codex（Pro系のプラン）：`rate_limit.primary_window` が週（`limit_window_seconds` = 604800、`used_percent` は0〜100の整数、`reset_at` はUnix秒）。`secondary_window`、`code_review_rate_limit`、`additional_rate_limits` はすべて null。設計どおり。

### 実データでの確認の手順（記録）

- 実装の前に、ClaudeとCodexの取得先へ、既存のログインで1回ずつ問い合わせる。使い捨てのスクリプトで行い、コードには残さない。
- 表示するのは応答の形だけ：項目名、`kind` と `group` の値、割合の範囲（0〜1か0〜100か）、時刻の形式。トークンや、割合の実際の値は表示しない。
- 確認した形を、架空の値に置き換えてテストの入力にする。
- GitHubの報告と違う点が見つかったとき：
  - 項目名や形式の違いなど、この設計の考え方の範囲で吸収できるものは、実装者が直して記録する。
  - 表示する枠の考え方そのものが変わるもの（例：Codexに5時間・週以外の枠がある）は、止めて利用者に聞く。
- 利用者の許可が得られない場合は、GitHubの報告の形で実装する。割合が0〜1で来た場合にも気づけるよう、`percent` が1以下の値ばかりなら記録に残す。

## 検証

- 自動テスト（架空の値）：
  - Claudeの解析：Ultra（`weekly_all` と `weekly_scoped`、`session` なし）、Max（3つ全部）、Pro（`session` と `weekly_all`）、認証前のUltra（`session` あり）、`limits` なしの従来形式、`limits` が空、壊れた項目、知らない `kind`、重複、長すぎるモデル名や制御文字を含むモデル名、`usage-cache.json` の形式。
  - Codexの解析：Plus（5時間と週）、Pro（週だけ）、5時間だけ、記録の300分と10080分。
  - プラン名：`max` + `20x` は「Ultra」、`max` + `5x` は「Max」。履歴の「Max 20x」は「Ultra」に置き換わり、学習が続く。
  - 警告と予測：`Span` で規則が選ばれる。「週（Fable）」に週の規則が使われる。
  - 表示データ v2：作成、64 KiB以下、Obsidian・Stream Deckでの解析。v1は受け付けない。枠が0〜4個。
  - トレイの一覧（UIテスト）、ウィジェット、Obsidianのツールバー、Stream Deckのキー：枠が0〜3（4）個の表示。
- 実機：
  - トレイの一覧、Obsidian、Stream Deckに、Ultraのアカウントで「週」と「週（Fable）」が出て、「5時間」は出ないこと。
  - 値が、claude.aiの設定画面（Settings > Usage）と一致すること。

## 作る人に任せること

- `Span`／`Scope` の型と名前。短い名前の作り方。
- 各画面で3〜4枠を並べる配置の細部。
- テスト用の応答例の作り方。
- 履歴の名前の置き換えを、読み込み時と保存時のどちらで行うか。
