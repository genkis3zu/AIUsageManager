# 「AIの状況」表示（障害情報とリセットの知らせ）

## 目的と決めたこと

使えないときに「障害のせいか、上限のせいか」をすぐ区別できるようにする。利用者が承認した内容は次のとおり。

- Stream Deckに「AIの状況」キーを1つ足す。トレイの一覧にも同じ内容を1行出す。
- 表示は優先順に：障害（赤）→ 一部不調（黄）→ 少し前に枠がリセットされた（緑、リセットから1時間）→ 正常。
- 障害情報：Anthropic（`status.claude.com`）とOpenAI（`status.openai.com`）。xAIは障害情報ページがプログラムからの読み取りを拒否するので対象外。
- 障害情報ページはトレイアプリが5分ごとの更新で読む。Stream Deckのプラグインは今までどおりどこにも通信しない。ログイン情報は送らない。
- キーを押すと、表示している会社の障害情報ページをブラウザで開く。

## 設計

- **読むもの**：`https://status.claude.com/api/v2/summary.json` と `https://status.openai.com/api/v2/summary.json` をGETする。認証ヘッダー・Cookieは付けない。転送は追わない。1回10秒・1 MiBまで。失敗したら「確認できません」。
- **判定**（Atlassian Statuspage互換の形式）：部分（component）の `status` が `major_outage` なら障害、`partial_outage`・`degraded_performance`・`under_maintenance` なら一部不調。全体の `status.indicator` は `major`・`critical` が障害、`minor`・`maintenance` が一部不調。
  - Claude：`claude.ai`・`Claude Code`・`Claude API` で始まる部分だけで判定する。該当する部分が1つもなければ全体の状態を使う。
  - OpenAI：全体の状態と、名前に `Codex` または `ChatGPT` を含む部分の、悪いほうを使う（Codexの部分がデータに一部しか載っていないため）。
  - 表示に添える部分名は、不調な部分を最大3つ。外部の文字列なので制御文字を除き、1つ40文字までにする。
- **リセットの知らせ**：同じ枠のリセット時刻が、前回の値を過ぎて新しい時刻に進んだら、その枠のリセットとみなす。対象は週の枠だけ（5時間の枠は頻繁なので出さない）。オンラインで新しく取れた値だけを使う。表示はリセット時刻から1時間。
- **共有データ**：トップレベルに `status`（`tone`、`title`、`detail`、`page`）を足す。schemaVersion は 2 のまま（今の受け手は知らない項目を読み飛ばす）。受け手は `page` を2つの決まったURLだけに限る。
- **トレイ**：見出しの下の「AI Usage Manager」の行を、状況の1行（例「Claude 障害（Claude Code）」「正常」）に置き換える。色は状況に合わせる。
- **Stream Deck**：アクション「AIの状況」（設定画面なし）。押すと `openUrl` で `page` を開く。`page` がないときはClaudeの障害情報ページ。未接続のときは、ほかのキーと同じくトレイアプリを起動する。プラグインの版は 1.2.0。
- **文書**：README、データ取得仕様、プライバシー（新しい通信先）、Stream Deckガイド。

## 対象外

- xAI（Grok）の障害情報、Windowsウィジェット、Obsidian。
- 障害のWindows通知（今回は表示だけ）。

## 失敗とみなすこと

- 障害情報ページにログイン情報やCookieを送る。プラグインが外部に通信する。決めた2つ以外のURLを開く。
- 障害情報が取れないのに「正常」と表示する。
- Claudeと関係ない部分（例：政府向けサービス）の不調で、Claudeを不調と表示する。
- 5時間の枠のリセットや、保存値・記録からの値で、リセットの知らせを出す。
