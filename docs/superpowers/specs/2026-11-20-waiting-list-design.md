# 対応待ちの一覧（Claude・Codex・Grok Bot）

## 目的

AIを何本も並行して動かしていると、どれかが利用者の返事（質問への答え、操作の確認）を待って止まっていても気づかない。調査では、承認待ちに20分気づかなかった例や、通知が届かない・集中モードで消えるという報告が多かった（`reports/AIエージェント状態表示と新機能調査.md`）。返事を待っているAIを1か所に、待たせている時間の長い順に並べ、待ちが続いたら知らせ直す。

## 利用者が決めたこと

- 想定する使い方：Claude Code はClaudeデスクトップアプリとVS Code、Codex はChatGPT/Codexデスクトップアプリ（VS Code からも）、Grok は Grok Bot デスクトップアプリ。ターミナルのCLIは対象にしない。
- 作り方は **A：各AIの設定を変えず、記録と通知を読むだけ**。フックの登録（B）は、必要になったら後で、利用者が選んだときだけ加える。
- Grok Bot は、Windows の通知を読んで一覧に入れる（Windows の「通知へのアクセス」をこのアプリに許可する）。.NET Framework 4.8 のアプリから読めるかを、作る前に確かめる。読むのにアプリのパッケージ化（Windows への登録）が必要なら、パッケージを作って入れる。
- 見せ方：
  - トレイ：見出しの下に「対応待ち N件」。対応待ちを待ち時間の長い順に上へ、完了は下に完了から30分だけ。
  - Stream Deck：「対応待ち」キーを足す。いちばん長く待たせているものを出し、押すとそのAIのアプリを前に出す。
  - 待ちが3分続いたらWindows通知、その後10分ごとに知らせ直す。間隔は変えられる。完了は知らせ直さない。

## 言葉

| 言葉 | 意味 |
|---|---|
| 対応待ち | AIが利用者の返事を待って止まっている状態。理由は「質問」か「確認」 |
| 質問 | AIが利用者に質問し、答えを待っている |
| 確認 | 質問以外で利用者の操作を待っている（操作の許可の画面など） |
| 完了 | 1回の依頼への作業が終わり、次の指示を待っている |
| 待ち時間 | 対応待ちまたは完了になってからの時間 |

## 目標・対象外・避けること

- 目標：上の3つのAIの対応待ちを、トレイとStream Deckで同じ内容で見られる。3分以上の待ちを見落とさない。
- 対象外（今回）：キーやダイヤルでの承認、各AIの設定へのフック登録、Codex の承認待ち（記録に残らない）、Stream Deck + のダイヤルとタッチストリップ、Obsidian・Windowsウィジェットへの表示、アプリの中の特定の会話を開くこと、Grok Build（CLI）。
- 避けること：
  - 会話の内容を読む・保存する・表示すること。読むのは状態・時刻・作業フォルダー名・セッション名だけ。Grok Bot の通知の本文は種類の判定にだけ使い、保存も表示もしない。
  - 各AIの設定ファイルや記録に書き込むこと。
  - 読めないのに「対応待ちなし」と言うこと。記録を読めないAIがあるときは、そう表示する。
  - 新しい通信。今回の機能はすべてこのPCの中で完結する。

## 作り方の案

- **A（選択）：記録と通知を読むだけ**。設定を変えないので、アプリの「CLIの設定を変えない」という約束と両立する。Claude Code は公式の説明がない状態ファイルに頼るため、Claude Code の更新で形が変わる危険がある。Codex の承認待ちは出ない。
- **B：各AIのフックを登録する**。公式の仕組みで承認待ちも確実に拾え、将来のキーでの承認につながる。ただし設定ファイルへの書き込みが要り、デスクトップアプリとVS Codeでフックが動くかは未確認。利用者の Claude Code の設定にはすでに別のフックが登録されており、併合が要る。
- A を選んだ理由：想定する使い方（デスクトップアプリとVS Code）で、設定を変えずに主な対応待ちが取れることを確かめたため。

## 設計

### Claude Code（デスクトップアプリ・VS Code）

- 読むもの：`%USERPROFILE%\.claude\sessions\*.json`。Claude Code が動いているセッションごとに書くファイル（公式の説明はない）。1ファイル64 KiBまで、最大300ファイル。読めないファイルは飛ばす。
- 使う項目：`pid`、`sessionId`、`status`、`waitingFor`、`statusUpdatedAt`（ミリ秒のUnix時刻）、`cwd`（フォルダー名だけ）、`name`（セッション名）、`entrypoint`（開くアプリの判定だけ）。
- 一覧に出す名前：セッション名（Claudeのアプリの一覧に出る題名）を優先する。なければプロジェクトのフォルダー名。`cwd` が `…\<プロジェクト>\.claude\worktrees\<自動の名前>` の形なら `<プロジェクト>` を使い、そうでなければ最後のフォルダー名。
- 動いているセッションだけを使う：`pid` のプロセスが存在し、プロセス名が `claude` であること。
- 判定：
  - `status` が `waiting` → 対応待ち。`waitingFor` が `input needed` なら「質問」、それ以外なら「確認」。待ち時間の起点は `statusUpdatedAt`。
  - `status` が `idle` で、トレイアプリが前回 `busy` を見ていた → 完了。起点は `statusUpdatedAt`。アプリ起動後に最初に見た状態は記録だけ（起動前の完了は出さない）。
  - それ以外（`busy` など）は出さない。
- 確認済み（2026-11-20）：デスクトップアプリで質問を出している間、`status` が `waiting`、`waitingFor` が `input needed` になり、答えると `busy` に戻った。
- 未確認：操作の許可の画面を出している間の値（デスクトップアプリ・VS Code）。作るときに実機で確かめ、取れなければ文書に書く。VS Code の `entrypoint` の値も実機で確かめる。

### Codex（ChatGPT/Codexデスクトップアプリ・VS Code）

- 読むもの：`%USERPROFILE%\.codex\sessions` 以下の `*.jsonl`。すでに使用量の予備の取得で読んでいるのと同じ記録。最後の書き込みが12時間以内のファイルだけ。ファイルの更新時刻が前回と同じなら読み直さない。
- 使う項目：各行の `timestamp`・`type`・`payload.type`、`function_call` の `name` と `call_id`、`function_call_output` の `call_id`、`session_meta` の `cwd`（最後のフォルダー名だけ）・`originator`・`source`。一覧に出す名前は `cwd` の最後のフォルダー名。
- 判定（ファイルの末尾から見て、最後に起きたこと）：
  - `function_call` で `name` が `request_user_input_async`、かつ同じ `call_id` の `function_call_output` がまだない → 対応待ち（「質問」）。起点はその行の `timestamp`。
  - `event_msg` の `task_complete` → 完了。起点はその行の `timestamp`。
  - `task_started` → 作業中（出さない）。
- ChatGPTまたはCodexのアプリ、VS Code のどれも動いていないときは、Codex の対応待ちを出さない（アプリを閉じて放置したセッションを出し続けないため）。
- Codex の承認待ちは記録に残らないため出さない（文書に書く）。

### Grok Bot（デスクトップアプリ）

- 作る前の確認：.NET Framework 4.8 の単体のexeから、Windows の `UserNotificationListener` で通知を読めるか。Microsoft の説明ではパッケージ（MSIX）の宣言が前提とされており、パッケージでないアプリに許可が出るかが分からない。
- パッケージが必要な場合（利用者の決定）：パッケージを作って入れる。
  - 方法は確認の結果で決める（単体のexeに Windows 上の身元だけを与える小さなパッケージ、またはウィジェット用に作っているパッケージ版のアプリを使う）。
  - 導入の手順が1つ増え、開発者モードか証明書の登録が要る見込み（ウィジェットと同じ程度）。手順はガイドに書く。
  - パッケージなしで起動したときは、一覧の下に「Grok Bot：通知を読むにはパッケージの導入が必要です」と出す。Claude と Codex の一覧はパッケージなしでも動く。
- 読めるとき：
  - 送り主が Grok Bot（AppUserModelID `electron.app.Grok Bot`）の通知だけを使う。
  - 本文の言葉から「待っている」と分かれば対応待ち（「確認」）、それ以外は完了。どちらも起点は通知の時刻。判定の言葉は実際の通知を見て決める。本文は判定に使ったら捨てる。
  - 項目を消すのは、Grok Bot のウィンドウが前に出たとき、その通知が通知センターから消えたとき、または1時間たったとき。完了は30分で消す。
  - トレイアプリの起動時にすでに通知センターにある通知は、記録だけして一覧に出さない。
  - 通知へのアクセスが許可されていないときは、一覧の下に「Grok Bot：通知へのアクセスが許可されていません」と出す。

### 一覧と知らせ直し

- トレイアプリが5秒ごとに上の3つを読み、一覧を作る。前回と変わったときだけ画面と共有データを更新する。
- 並べ方：対応待ちを待ち時間の長い順、その下に完了を新しい順。完了は30分で消す。
- 知らせ直し：対応待ちが3分続いたらWindows通知、その後も対応待ちのままなら10分ごと。待ちが1時間を超えたら知らせ直しをやめる（一覧には残す）。通知の文は「Claude（AIUsageManager）が質問の答えを3分待っています」の形。
- Windows の「応答不可」（集中モード）が有効なときは、Windows がこの通知を止めることがある。特別な対応はせず、Stream Deck のキーとトレイの一覧で見えることを文書に書く。
- 間隔の設定：トレイの右クリックに「対応待ちの通知」を足す。選べるのは「3分後、その後10分ごと」（最初の設定）、「1分後、その後5分ごと」、「通知しない」。`settings.ini` に保存する。

### トレイの表示

- 見出しの下（AIの状況の1行の下）、使用量の一覧の上に出す。項目がないときは出さない。
- 1行に1項目：AIの名前、作業フォルダー名（なければセッション名、どちらもなければ空）、理由（質問・確認・完了）、待ち時間。最大4行と「ほか N件」。
- 行をクリックすると、そのAIのアプリを開く（下の「アプリを開く」）。
- 記録を読めないAIがあるときは、最後に「Codexの記録を読めません」のように1行出す。

### Stream Deck

- アクション「対応待ち」を足す（設定画面なし）。プラグインの版は 1.3.0。
- キーの表示：
  - 対応待ちがあるとき：件数、いちばん長く待たせている項目のAIの名前・作業フォルダー名・待ち時間。黄色、待ち時間10分以上で赤。
  - 対応待ちがなく完了があるとき：「対応待ちなし」と「完了 N件」。
  - どちらもないとき：「対応待ちなし」。
  - 未接続・読み込み中は、ほかのキーと同じ。
- キーを押す：いちばん長く待たせている対応待ち（なければ最新の完了）のアプリを、Stream Deck の `openUrl` で開く（下の「アプリを開く」）。項目がないときは何もしない。未接続のときは、ほかのキーと同じくトレイアプリを起動する。
- プラグインがトレイアプリの共有データを読む間隔を15秒から5秒にする（同じPCの中の読み取りだけ）。

### アプリを開く

- 各アプリが Windows に登録しているリンクで開く：Claude のデスクトップアプリは `claude://`、Codex のデスクトップアプリは `codex://`、VS Code は `vscode://`、Grok Bot は `grokbot://`（このPCで4つとも登録を確認済み）。どれを使うかは Claude Code の `entrypoint`、Codex の `originator`・`source` から決める。
- Windows は、裏で動いているプログラムが別のウィンドウを前に出すことを制限している。リンクで開くと、開かれたアプリ自身が前に出るので、この制限を避けられる。キー入力を送るような方法は使わない。
- 開けるのはこの4つの決まったリンクだけ（Stream Deck のプラグインと共有データの読み取りで限る）。実際にリンクでアプリが前に出るかは作るときに確かめ、出ないものがあれば利用者に相談する。
- 確認（2026-11-20）：`claude://` は Claude、`codex://` は ChatGPT（Codex）、`vscode://` は VS Code が前に出た（VS Code は起動していなければ起動する）。`grokbot://` と `grokbot://app` では Grok Bot は前に出なかった。Grok Bot を前に出す方法は、Grok Bot の計画で別に決める。
- アプリの中の特定の会話までは開かない。

### 共有データ

- トップレベルに `waiting` を足す（schemaVersion は 2 のまま）：項目の配列（最大8）。各項目は `service`（Claude・Codex・Grok Bot）、`place`（セッション名または作業フォルダー名、40文字まで、制御文字を除く）、`reason`（`question`・`confirm`・`finished`）、`since`（ISO 8601）、`app`（`claude`・`codex`・`vscode`・`grokbot`）。読めないAIの名前と理由を別の配列に入れる。
- 受け手（Stream Deck プラグイン）は、知らない値や形の合わない項目を捨てる。

### 文書

- README（できること）、`docs/data-sources.md`（読む記録と判定）、`docs/privacy.md`（新しく読むファイルと通知、内容を読まないこと、通知へのアクセスの許可、開けるリンク）、`docs/streamdeck-guide.md`（「対応待ち」キー）、必要ならパッケージの導入手順。
