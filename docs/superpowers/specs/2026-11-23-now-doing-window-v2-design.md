# 「いまやってること」の窓 第2版（ボタン・スクリプト・長い文の送信・2回押しのショートカット・AI の完了の記録）

前の版: `docs/superpowers/specs/2026-11-23-now-doing-key-design.md`（キー・窓・日中ログへの1行・Claudian への送信・ショートカットキー）。この文書は、その上に足すものだけを書く。

## 目的

利用者は、作業の途中の報告（休憩などの区切り・測った数値・ほかの AI の結果を貼る・質問する）を Obsidian の Claudian のチャットに打っている。そのたびに Obsidian に移るので、別のアプリでの作業の流れが切れる。

この窓から同じことをできるようにする。返事の要らない記録は窓だけで済ませ、Obsidian は前に出さない。質問や依頼は今までどおり Claudian に送り、Obsidian が前に出て返事を読む。

## 利用者が決めたこと（2026-11-23）

- 返事の要らない記録は窓だけで済ませる。質問・依頼は Ctrl+Enter で Claudian へ送る（Obsidian が前に出る）。
- **窓に組み込みすぎない。** 仕組みを変えたときにアプリの変更が大きくならないように、日誌の決まり（どの行に ✅ を付けるか、frontmatter のどのキーに書くか、何をまだのこととして出すか）はアプリに持たせず、利用者のスクリプトに置く。アプリがするのは「日中ログに書く・Claudian に送る・設定されたスクリプトを実行して結果を出す」だけ。
- 窓を開くショートカットを **Ctrl や Shift の2回押し** にできるようにし、何種類かから選べるようにする。（2026-11-23 追記）Alt の2回押しも選べるようにする。そのために、キーボード全体の入力を受ける仕組み（`WH_KEYBOARD_LL` のフック）を入れてよい。
- （Claudian の判断・利用者が違えば直す）2回押しで開いた窓が前に出られないときは、何もしないキーを1つ送って前に出す（下の「窓を前に出す」）。
- 画像（スクリーンショット）は今回は入れない。

## 言葉

| 言葉 | 意味 |
|---|---|
| 記録 | Enter で日中ログに書く1行。Claudian には送らない |
| 送る | Ctrl+Enter。日中ログに1行書いたうえで、全文を Claudian に送る |
| ボタン | 窓の中のボタン。名前と動きは settings.ini で決める |
| 書いたあとのスクリプト | 日中ログに書いたあとに窓が実行する、利用者のプログラム（`now_doing_after`） |
| 一覧のスクリプト | 窓を開いたときに実行し、出力を窓の上に「まだのこと」として出す、利用者のプログラム（`now_doing_list`） |
| AI の完了 | 対応待ちの一覧で、新しく「完了」になったもの |

## 目標・対象外・避けること

- 目標:
  - ボタンか入力で、区切りや数値などの記録を、Obsidian を出さずに日中ログへ書ける。書いたあと、利用者のスクリプトが日誌のほかの場所（✅・frontmatter など）を直せる。
  - 複数行・長い文（ほかの AI の結果など）を Claudian に送れる。送るときは、書いた日誌を Obsidian で開いた状態にしてから送る。
  - 窓の上に、一覧のスクリプトが出した「まだのこと」を出す。
  - Ctrl・Shift・Alt の2回押し（設定で選ぶ）で窓を開ける。
  - AI の完了を、日中ログに1行で残せる（設定でオンにしたときだけ）。
- 対象外（今回）: 画像、Stream Deck の新しいキー、Claudian の返事を窓に出すこと、スクリプトの中身（利用者が作る）、窓からの記録の修正・削除、「まだのこと」を押して何かすること。
- 避けること:
  - 日誌の作り（見出しの名前・終わりの目印の設定以外）をアプリのコードに書くこと。
  - キーボードの入力を残すこと。フックが見るのは「左右の Ctrl・Shift・Alt の押し離し」と「それ以外のキーが押された」という事実と時刻だけ。それ以外のキーが何かは見ない。何も保存しない。
  - 前にあるアプリへのキーを止めたり変えたりすること（2回押しのキーも止めない）。例外は「窓を前に出す」の2だけ。
  - スクリプトをシェル経由で実行すること。入れた文を命令の文字列に埋め込むこと。
  - 新しい通信。

## 作り方の案

- **A（選んだ）: 窓は入れ物にする。** ボタンとスクリプトは settings.ini で決め、日誌の決まりはスクリプトに置く。
- B: 窓が、チェックの ✅・frontmatter の数値・日誌の中の表まで直す。すぐに全部そろうが、日誌のテンプレートを変えるたびにアプリの変更が要る。
- C: 窓は日中ログの1行だけを書き、✅ や frontmatter はあとで Claude（夜の振り返り）が直す。いちばん単純だが、✅ が夜まで付かない。
- A を選んだ理由: 利用者の「仕組みを変えたときに変更が大きくなりすぎる」を避けつつ、スクリプトが書いた直後に動くので ✅ も遅れない。

## 設計

### 入力欄とキー

- 入力欄を複数行にする。最初は1行の高さで、行が増えると6行まで伸びる。それより多いときはスクロールする。
- **Enter: 記録**（今までどおり）。複数行のときは改行を空白1つにして1行にする。200文字まで。
- **Shift+Enter: 改行。**
- **Ctrl+Enter: 送る**（`now_doing_claudian=on` のとき）。日中ログには、1行目の先頭80文字を書く。2行以上あるときは、その後ろに `（Claudian へ・N行）` を付ける。Claudian には全文を送る。全文は4000文字まで（超えたら送らずに「4000文字までです」）。
- 貼り付け（Ctrl+V）は、複数行の文をそのまま入れる。画像は入れない。
- **Alt+1〜Alt+9: ボタン1〜9。**
- Esc: 閉じる（今までどおり）。

### Claudian に送るとき

- 今の仕組み（1回だけ使える合言葉・`claudian-message.json`・`obsidian://ai-usage-manager-claudian`）を使う。
- `claudian-message.json` に、書いた日誌のファイルの場所（`note`）を足す。
- Obsidian のプラグインは、`note` が開いている保管庫の中のファイルなら、それを今のタブで開いてから Claudian に送る。保管庫の外のとき・見つからないときは、開かずに送る。
- プラグインも、受け取る文の長さを4000文字までとして確かめる。

### ボタン

- settings.ini の `now_doing_button1` 〜 `now_doing_button9`。書き方は `<名前>|<動き>:<中身>`。
- 動きは3つ:

| 動き | すること | 例 |
|---|---|---|
| `text:<文>` | 入力欄にこの文を入れる（カーソルは末尾）。続きを打って Enter | `⏱️ 作業\|text:⏱️ ` |
| `record:<文>` | この文をそのまま記録する（入れて Enter を押したのと同じ。書いたあとのスクリプトも動く） | `🚶 散歩\|record:🚶 散歩 ✅` |
| `copy:<命令>` | 命令を実行し、標準出力をクリップボードに入れる。後ろに `\|open:<リンク>` を付けると、そのあとリンクを開く。開けるのは、対応待ちのキーと同じ決まったリンク（`claude://` `codex://` `vscode://` `grokbot://`）だけ | `📈 依頼文\|copy:python C:\Notes\scripts\request.py\|open:claude://` |

- ボタンは入力欄の下に1列で並べる。窓の幅に入らない分は2列目に回す。名前が長いときは8文字で切る。
- 書き方が違うボタンは出さず、窓の下に「settings.ini の now_doing_buttonN の書き方が違います」と出す。

### スクリプトの実行

対象は、書いたあとのスクリプト（`now_doing_after`）・一覧のスクリプト（`now_doing_list`）・ボタンの `copy`。

- settings.ini に、実行ファイルと引数をそのまま書く（例 `python -X utf8 "C:\Notes\scripts\after.py"`）。先頭の語を実行ファイル、残りを引数として分ける。`"` で囲めば空白を含められる。
- シェルは使わない（`UseShellExecute=false`）。窓を出さない（`CreateNoWindow=true`）。
- 窓が後ろに足す引数:
  - 書いたあとのスクリプト: `--note <日誌の場所> --time <HH:MM> --mode <record か send> --text <入れた文>`。入れた文は、窓が日中ログで先頭に付ける `📝 ` を除いたもの。Ctrl+Enter（`send`）のときも、日中ログに書いた1行ではなく入れた全文を渡す（スクリプトが `--mode` で分けられるように）
  - 一覧のスクリプト・copy: `--note <日誌の場所>`
  - 文は引数1つとして渡す（命令の文字列に埋め込まない）。
- 作業フォルダー: `now_doing_workdir`。なければアプリのフォルダー。
- 標準出力は UTF-8 として読む。書いたあとのスクリプトと一覧のスクリプトは4096バイト・20行まで。copy は32KBまで（行数の上限なし・依頼文は20行を超えるため）。上限を超えたら失敗として扱い、copy ならクリップボードを変えない（途中で切れた文を貼らせないため）。標準エラーは、失敗の理由として最初の1行だけを使う。
- 時間の上限: 書いたあとのスクリプトと copy は10秒、一覧のスクリプトは3秒。越えたらプロセスを終わらせ、失敗として扱う。
- スクリプトを待つ間も窓は固まらない（裏で実行する）。
- 失敗（終了コードが0以外・時間切れ・起動できない）のとき:
  - 書いたあとのスクリプト: 日中ログの1行は書けているので消さない。窓は閉じずに「日誌には書きました。そのあとの処理に失敗しました: <理由>」と出し、入力欄を空にする（もう一度 Enter で二重に書かないため）。
  - 一覧のスクリプト: 「まだのこと」の欄を出さず、窓の下に小さく「まだのことを出せませんでした」と出す。
  - copy: クリップボードを変えず、リンクも開かない。理由を出す。
- 書いたあとのスクリプトが成功したとき: 出力の1行目を窓に1.5秒出してから閉じる。出力が空ならすぐ閉じる。
- 書いたあとのスクリプトは、日中ログに書いたときは毎回実行する（Enter・`record`・Ctrl+Enter のどれでも）。Ctrl+Enter のときは、スクリプトが終わってから Claudian に送る（失敗しても送る）。

### 窓の上の「まだのこと」

- `now_doing_list` があれば、窓を開いたときに実行する。出力の行（最大5行）を入力欄の上に「まだのこと」として出す。長い行は1行に収まるように切る。
- 今の「今日の記録」（📝 の一覧）はそのまま下に残す。窓の高さが足りなければ、今日の記録の件数を減らす（最低3件）。
- 表示だけ。押しても何も起きない。

### 2回押しのショートカット（Ctrl・Shift・Alt から選ぶ）

- `now_doing_hotkey` に、次のどれかを書ける。今の `Ctrl+Alt+N` の形もそのまま使える。

| 値 | 押すキー |
|---|---|
| `DoubleCtrl` | Ctrl を2回（左右どちらでも。1回目と2回目で左右が違ってもよい） |
| `DoubleLeftCtrl` | 左 Ctrl を2回 |
| `DoubleRightCtrl` | 右 Ctrl を2回 |
| `DoubleShift` | Shift を2回（左右どちらでも） |
| `DoubleLeftShift` | 左 Shift を2回 |
| `DoubleRightShift` | 右 Shift を2回 |
| `DoubleAlt` | Alt を2回（左右どちらでも） |
| `DoubleLeftAlt` | 左 Alt を2回 |
| `DoubleRightAlt` | 右 Alt を2回 |

- （2026-11-23 変更・本人の希望）Alt の2回押しも選べるようにする。初めは「多くのアプリで、Alt だけを押すとメニューに移る・Office のキーの案内が出るなど、前にあるアプリの動きが変わる」ため選べないようにしていた。フックはキーを止めないので、この動きは起きる（2回目の Alt でメニューから戻ることが多い）。案内にそう書く。
- 右 Alt を AltGr として使うキーボード配列（ドイツ語など）では、右 Alt を押すと Windows が左 Ctrl も押したことにするため、`DoubleRightAlt` は働かない。日本語のキーボードでは働く。
- PowerToys の「マウスを探す」は、既定で左 Ctrl の2回押しを使う。両方を使うと、同じ操作で両方が動く。案内に「マウスを探すを使うなら、それと重ならないもの（右 Ctrl・Shift など）を選ぶ」と書く。
- トレイアプリが動いている間、設定が `Double…` のときだけ `SetWindowsHookEx(WH_KEYBOARD_LL)` を入れる。
- 判定（「選んだキー」は上の表で決まるキー）:
  1. 選んだキーを押して離す（押している時間が300ミリ秒以内）。
  2. 離してから400ミリ秒以内に、選んだキーをもう一度押して離す（押している時間が300ミリ秒以内）。
  3. 1から2の間に、選んだキー以外のキーが押されたら、数え直す。選んだキーを押したままほかのキーを押した（Ctrl+C・Shift+A など）ときも数えない。
  4. キーを押しっぱなしにしたときの繰り返し（同じキーの押下が続く）は、押した1回として扱う。
  5. マウスは見ない（見るものを増やさないため）。選んだキーを押したままのクリックを素早く2回したときに窓が開くことがあるが、Esc で閉じればよいとして受け入れる。
- フックの中で見るのは、キーが左右の Ctrl・Shift・Alt のどれかどうかと、時刻だけ。ほかのキーは「ほかのキーが押された」という印を立てるだけで、どのキーかは見ない・残さない。すべて `CallNextHookEx` でそのまま渡し、止めない。
- **窓を前に出す:** 普通の登録（`RegisterHotKey`）と違い、フックで見つけたときは、Windows から「前に出してよい」という許可がもらえない可能性が高い。
  1. まず、キーを送らない方法（`AttachThreadInput` など）で前に出せるか試す。
  2. それでも出せないときは、何もしないキー（どの機能にも割り当てられていない仮想キー）を1つ `SendInput` で送ってから、前に出す。このときだけ、前の版の「キー入力をまねる回避策は使わない」の例外にする。送るのは2回押しで開いたときだけで、Stream Deck のキー・普通の登録のショートカットでは送らない。
  3. 何を試し、どれで前に出たかを、作業の記録と案内に書く。
- フックの処理は短くする。窓を開くのは、フックの外（トレイのメッセージ処理）で行う。Windows は応答の遅いフックを外すため。
- 管理者として動いている窓が前にあるときは、Windows の決まりで届かない。案内に書く。
- フックを入れられなかったときは、トレイの通知で知らせる（今の「ショートカットキーを登録できない」ときと同じ）。
- `docs/privacy.md` に、このフックが見るもの・見ないもの・残さないことを書く。

### AI の完了を日中ログへ

- `now_doing_ai_done=on` のときだけ。トレイアプリが、対応待ちの一覧で新しく「完了」になったものを日中ログに書く。
- 書く形は、窓の記録と同じ2行: `[HH:MM]` と `🤖 <アプリ> 完了: <名前>`。`<名前>` は対応待ちの一覧に出している名前。位置の決め方と書き方は、窓の書き込みの処理をそのまま使う。
- まとめ方:
  - 最初の完了から2分待ち、その間に続いた完了を1行にまとめる（`🤖 完了: Claude「A」・Codex「B」`）。時刻は最初の完了の時刻。
  - （2026-11-23 追記）同じアプリで名前も同じもの（同じフォルダーで動いた別のスレッドなど）は、名前を1回だけ書いて数を付ける（`🤖 Codex 完了: A（2件）`、`🤖 完了: Codex「A」（2件）・Claude「B」`）。実機で `Codex「A」・Codex「A」` と並んだため。
  - 同じもの（同じセッション・スレッド）は、30分に1回まで。
- 除くもの: `now_doing_ai_done_exclude=<フォルダーの場所>;<フォルダーの場所>`（フルパス）。作業フォルダーの実際の場所が、そのフォルダーかその下にあるものは書かない（例: 日誌の保管庫の中で動く Claude のチャットや、保管庫の下で定期的に動くエージェントを除くため）。一覧に出す名前（プロジェクト名）ではなく、実際の作業フォルダーの場所で比べる（worktree も実際の場所で比べる）。
- 書く前に、日誌が直前10秒以内に変わっていたら（Obsidian で打っている最中かもしれないため）、10秒おきに待ち直す。5分たっても変わり続けていたら書かない。
- 日誌がない・書けないときは書かない。通知もしない。
- 書いたあとのスクリプトは、AI の完了の行では実行しない。

### settings.ini に足すキー

| キー | 中身 | ないとき |
|---|---|---|
| `now_doing_button1`〜`9` | ボタン（上の書き方） | ボタンなし |
| `now_doing_after` | 書いたあとのスクリプトの命令 | 実行しない |
| `now_doing_list` | 一覧のスクリプトの命令 | 「まだのこと」を出さない |
| `now_doing_workdir` | スクリプトの作業フォルダー | アプリのフォルダー |
| `now_doing_hotkey` | `DoubleCtrl`・`DoubleLeftCtrl`・`DoubleRightCtrl`・`DoubleShift`・`DoubleLeftShift`・`DoubleRightShift`・`DoubleAlt`・`DoubleLeftAlt`・`DoubleRightAlt` を足す | 今までどおり |
| `now_doing_ai_done` | `on` で AI の完了を書く | 書かない |
| `now_doing_ai_done_exclude` | 除く作業フォルダーの場所（フルパス・`;` 区切り・その下も除く） | 除かない |

- テーマなどを保存するときに、これらの行を消さないこと（前の版で直した決まりのまま）。

## 実機での確認（作ったあと・利用者と一緒に）

1. 設定した2回押し（`DoubleRightAlt`・`DoubleCtrl`・`DoubleShift` を試す）→ 窓が前に出て、クリックせずに打てる。右 Alt の2回押しで、前にあるアプリのメニューやキーの案内が出たままにならない。
2. Ctrl+C・Ctrl+V・Shift で大文字を打つ・Ctrl+Shift+… など普段の操作では窓が開かない。
3. Shift の2回押しで、日本語入力のモード（かな・英数）が変わってしまわない。
4. VS Code・ブラウザ・仕事で使う全画面の画面が前にあっても、1 のとおりに動く。
5. 「🚶 散歩」のボタン → 日中ログに1行入り、書いたあとのスクリプトの出力が出て、窓が閉じる。
6. 「⏱️ 作業」のボタン → `⏱️ ` が入る → 数字を打って Enter。
7. ほかの AI の4行の結果を貼って Ctrl+Enter → 日中ログに1行入り、Obsidian が前に出て、書いた日誌が開き、Claudian に全文が届く。
8. 「📈 依頼文」のボタン → クリップボードに文が入り、Claude Desktop が開く。
