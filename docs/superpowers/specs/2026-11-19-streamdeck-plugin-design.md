# Stream Deckプラグイン（トレイアプリの値を表示）

## 問題

Stream Deckで使用量を見るために第三者製プラグイン `kr.co.postgresql.ai-limits`（以下「既存プラグイン」）を入れたところ、トレイアプリでClaudeの使用量が取れなくなった。

- 既存プラグインは、トレイアプリと同じClaude Codeのログイン（`~/.claude/.credentials.json`）で、同じ取得先 `https://api.anthropic.com/api/oauth/usage` に問い合わせる。通常の間隔は約30秒。
- 既存プラグインには、取得に失敗すると待ち時間なしで再送を続ける不具合がある。`%TEMP%/ai-usage-claude-usage.json` から前回値を読み込んだとき、取得時刻が0のまま残る。失敗しても取得時刻は更新されない。そのため「値が古い → 再取得 → 失敗 → 再描画 → まだ古い → 再取得」が待ち時間なしで繰り返される。この処理はボタンの有無に関係なく、プラグインの起動時から動く。
- 既存プラグインのログには、1分あたり約1,500回の取得制限（HTTP 429）が記録されていた。
- 取得制限はアカウント単位でかかる。そのため、トレイアプリの5分に1回の問い合わせも429になる。
- Codexについては、既存プラグインはローカルのセッション記録を読むだけで、APIには問い合わせない。Grokは失敗の記録がない。問題が出ているのはClaudeだけ。

## 目的

Stream Deckでの使用量表示を続けながら、AIサービスへの問い合わせをトレイアプリ1か所にまとめる。既存プラグインを、トレイアプリの値を表示する自作のStream Deckプラグインに置き換える。

## 利用者が決めたこと

- 方法：自作のStream Deckプラグインに置き換える（後述のA案）。
- 見た目と操作は、既存プラグインの今の使い方に合わせる。
- トレイアプリが起動していないときは「未接続」と表示する。そのときボタンを押すとトレイアプリを起動する。プラグイン自身がAPIに問い合わせる代わりの手段は作らない。

## 目標

- Stream Deckのキーに、Claude（5時間・週）、Codex（週）、Grok（週）の使用量を表示する。
- プラグインはAIサービスのAPIにも、どの外部ホストにも通信しない。値は、トレイアプリが公開している共有データ（現在のユーザーに限定した名前付きパイプ）からだけ受け取る。
- 今の使い方を再現する。キー3つ、縦バー表示、使用率（Used）、リセットまでの時間。短押しで表示スタイルを切り替え（リング／縦／横）、長押しで色を切り替える。
- トレイアプリの表示ルールに合わせる。「未取得」と0%を区別し、古い値や取得失敗の値を新しい値として見せず、上限が近いときは警告の色にする。

## 対象外

- Stream Deck+のダイヤル・タッチストリップ、Antigravity。今の構成で使っていないため。
- macOS。
- Elgato Marketplaceでの公開。
- Windowsウィジェットを共有データ読み取りへ切り替えること。ウィジェットも5分ごとに `--widget-data` で別に取得しているが、今回の問題の原因ではない。別作業として扱う。
- 既存プラグインの修正。

## 失敗とみなすこと

動いていても、次のどれかに当てはまれば失敗とする。

- プラグインがAIサービスや外部ホストに通信する。認証ファイル（`.credentials.json`、`.codex/auth.json`、`.grok/auth.json`）を読む。
- 名前付きパイプから受け取った値をもとに、ファイルを実行する。
- 未取得を0%として表示する。15分以上前の値や取得失敗の値を、新しい値と同じ見た目で表示する。
- トレイアプリが動いているのに、名前付きパイプの一時的な混雑で「未接続」が点滅する。
- Stream Deckアプリを不安定にする。待ち時間なしの繰り返し処理などで、CPUや通信の負荷を出し続ける。

## 制約

- 名前付きパイプ：`\\.\pipe\AIUsageManager.Snapshot.<ユーザーSID>`。サーバーの同時接続は1件。接続すると、JSON（schemaVersion 1、最大64 KiB）を1回書いて閉じる。今のところ、パイプを読むのはObsidianプラグインだけ（`--obsidian-data` 経由）。Windowsウィジェットは `--widget-data` で別に取得しており、パイプは読まない。
- トレイアプリ（`src/Snapshot.cs` の `SnapshotServer.Run`）は、1件書き終えるとパイプを閉じてから作り直す。書き込みに失敗したときは1秒待ってから作り直す。そのため、トレイアプリが動いていても、パイプが存在しない瞬間がある。C#の読み手（`ConnectAsync(800)`）はこの間も再試行するが、Node.jsの `net.connect` は再試行せず、すぐに「存在しない」（ENOENT）を返す。
- パイプ名は推測できる。同じPCの別アカウントのプロセスが、先に同じ名前のパイプを作ることは防げない。Node.jsからは、接続先のサーバーが誰かを確かめにくい。そのため、パイプから受け取る値は表示だけに使い、実行するファイルの場所など、動作を決める値は受け取らない。
- 共有データの形式とその解釈は、`obsidian/src/usage.js` の `parseSnapshot` と `presentService` に実装済み。同じ規則を二重に書かない。
- Stream Deck 7.6.1（この環境）は Node.js 20.20 と 24.22 を同梱している。プラグインは同梱のNode.jsで動く。
- このリポジトリでは、npmの依存パッケージを入れない。Obsidianプラグインは、Node.js単体のビルドスクリプト（`tools/build-obsidian.cjs`）と `node --test` でビルド・テストしている。CIは `.github/workflows/build.yml`（windows-latest）。
- 既存プラグインのコード、サービスのロゴ、画像は写さない。ライセンス表記が見当たらないため。文字と図形は新しく作る。

## 検討した方法

| 案 | 内容 | 長所 | 短所 | 判断 |
|---|---|---|---|---|
| **A** | トレイアプリだけがAPIに問い合わせる。自作のStream Deckプラグインは共有データを表示する | 問い合わせが5分に1回にまとまり、根本から解決する。表示ルールもトレイアプリと揃う | 新しい部品を作る作業量がある。ボタンを置き直す必要がある | **採用** |
| B | 既存プラグインを手元で修正し、作者に報告する | 早い。見た目が変わらない | 他者のコードの書き換えになる。プラグインを更新すると元に戻る。30秒ごとの問い合わせは残る | 不採用 |
| C | トレイアプリが429のとき、既存プラグインの保存値（`%TEMP%`）を表示する | トレイアプリだけの変更で済む | 既存プラグインが送り続ける間は、どちらも新しい値が取れない | 不採用 |

## 設計

### 構成

- リポジトリに `streamdeck/` を追加する。中身はマニフェスト、プラグイン本体、設定パネル（Property Inspector）、テスト。Obsidianプラグインと同じく、Node.js単体のビルドスクリプトでまとめ、PowerShellスクリプトで配布ファイルを作る。
- アクションは3つ：Claude、Codex、Grok。既存プラグインと同じく、サービスごとに1つのキーを置く。
- 外部パッケージは使わない。Stream Deckとの接続には、同梱Node.js 24の標準 `WebSocket` と、Stream Deckのプラグイン登録手順（起動引数の `-port`、`-pluginUUID`、`-registerEvent`、`-info`）を使う。マニフェストではNode.js 24を指定する。

### 値の受け取り

- 表示中のキーが1つ以上ある間、15秒ごとに名前付きパイプを読む。読み取りは同時に1件までとし、1回あたり2秒で打ち切る。キーがなくなったら止める。
- パイプ名に使うユーザーSIDは、起動時に1回だけ取得する（例：`whoami /user`）。
- 読み取った内容は `parseSnapshot` で検証し、`presentService` で状態を決める。
- 「未接続」の判断（設計者の判断。トレイアプリ側のパイプの作り方は変えない）：
  - 1回の読み取りの中で、「存在しない」が返ったら少し間をあけて再試行する。再試行は、トレイアプリの作り直しの待ち（最大1秒）より長い約2秒まで続ける。それでも存在しなければ、トレイアプリは起動していないとみなし、「未接続」にする。トレイアプリを終了してから「未接続」になるまでは、最大で約17秒（読み取り間隔15秒＋再試行2秒）。
  - 混雑・タイムアウト・途中で切れたなど、その他の一時的な失敗のときは、直前の値を表示したままにする。2回続けて失敗したら（約30秒）「未接続」にする。
  - `connected:false` を受け取った場合は、すぐに「未接続」にする。
- 起動直後に、最初の値をすぐ読み取る。

### トレイアプリの場所（設計者の判断）

- 「未接続」のとき、トレイアプリを起動するには実行ファイルの場所が必要になる。
- トレイアプリは起動時に、自分の実行ファイルの絶対パスを `%LOCALAPPDATA%\AIUsageManager\app-location.json` に書く。予測履歴（`forecast-history.dat`）と同じフォルダーで、現在のユーザーしか書き込めない。パイプは使わない（理由は「制約」の3つ目）。
- プラグインは、起動が必要になったときにこのファイルを読む。値は `validPath`（`aiusagemanager.exe` で終わる絶対パス）で検証し、ファイルが実在することも確かめる。
- 設定パネルから手入力でも指定できる。手入力した場所は、上のファイルより優先する。
- 場所が分からない、または検証に通らない状態で押されたときは、起動せずにキーに「アプリの場所を設定」と表示する。
- 起動したトレイアプリが、Stream Deckアプリやプラグインの終了と一緒に止まらないようにする（親プロセスから切り離して起動する）。

### 表示（144×144 のSVGを `setImage` で送る）

- サービス名を文字で表示する。ロゴは使わない。
- 表示スタイル：リング／縦バー／横バー。Claudeは5時間と週の2本、Codex・Grokは週の1本。
- 数値：使用率（Used）または残り（Remaining）。設定で選ぶ。
- リセットまでの時間：表示する／しない。書式は `presentService` の `reset`（例：`2日5h`、`3h20m`、`期限経過`）。
- 色：サービスごとに選べる配色の一覧を用意する。初期値はClaudeがオレンジ系、Codex・Grokが緑系とし、今の見た目に合わせる。配色の値は新しく決める。
- 状態ごとの表示：
  - 未取得：バーを出さず「未取得」と表示する。
  - 保存された値・取得失敗：色を落とし、短い状態文を添える。
  - ログインが必要：「要ログイン」と表示する。
  - 警告（`presentService` の severity が warning または critical）：警告色にする。
  - 未接続：「未接続」と表示する。

### 操作

| 状態 | 短押し | 長押し（0.5秒超） |
|---|---|---|
| 接続中 | 表示スタイルを切り替える | 色を切り替える |
| 未接続（場所が分かる） | トレイアプリを引数なしで起動し、すぐ再読み取りする | 同左 |
| 未接続（場所が不明） | 「アプリの場所を設定」と表示する | 同左 |

切り替えた設定は、そのキーの設定として保存する。

### 設定パネル

表示スタイル、数値（使用率／残り）、リセットまでの時間の表示、色、トレイアプリの場所（全キー共通）。

### 配布と導入

- ビルドすると `build/streamdeck/<プラグインUUID>.sdPlugin/` ができる。配布ファイルは `dist/AIUsageManager-<版>-streamdeck.streamDeckPlugin`（`.sdPlugin` フォルダーを含むZIP）。ダブルクリックで導入できる。配布物には、明示した一覧のファイルだけを入れる。
- プラグインUUIDは既存プラグインと別にする（例：`io.github.genkis3zu.aiusagemanager`）。そのため既存プラグインの設定は引き継げない。導入手順に、既存プラグインの削除とキー3つの置き直しを書く。
- CIに次を追加する：プラグインのテスト（`node --test`）、ビルド、配布ファイルの内容確認。

### 文書

- `docs/streamdeck-guide.md` を新しく作る。導入、既存プラグインの削除、表示と操作、未接続時の動きを書く。
- README の機能説明と「はじめる」の表、`docs/privacy.md`、`docs/design.md` の構成表を更新する。`docs/privacy.md` には、名前付きパイプの読み手にStream Deckプラグインを加えることと、トレイアプリが `app-location.json` に実行ファイルの場所を保存することを書く。

## 検証

- 自動テスト
  - 共有データから表示内容を作る処理：各状態、Claudeの2枠、使用率と残りの切り替え、リセットまでの時間。
  - パイプ読み取り：一瞬だけ存在しない（再試行で読める）、ずっと存在しない、混雑・タイムアウト、2回続けて失敗、壊れたJSON、64 KiB超。テスト用の名前付きパイプサーバーを使う。
  - トレイアプリの場所：`app-location.json` の書き込み（C#側）と読み取り。ファイルがない・壊れている・`validPath` に通らない・実在しない場合、手入力が優先されること。
  - 操作：短押しと長押しの判定。未接続時は起動し、場所が不明なら起動しない。
  - 外部通信がないこと：プラグインのソースに、名前付きパイプとStream DeckのWebSocket（127.0.0.1）以外の接続先がないことを確認する。
- 実機確認（この環境の Stream Deck 7.6.1）
  - 3つのキーの表示。スタイルと色の切り替えが、再起動後も保たれること。
  - トレイアプリを終了すると、約17秒以内に「未接続」になること。押すとトレイアプリが起動し、値が表示されること。Stream Deckアプリを終了しても、起動したトレイアプリが動き続けること。
  - トレイアプリとObsidianが両方動いている状態で、しばらく「未接続」が出ないこと。
  - 既存プラグインを削除したあと、トレイアプリでClaudeが再び取得できること。取得制限が解けるまで時間がかかる可能性がある。

## 作る人に任せること

ファイル構成、WebSocketでのやり取りの細部、SVGの配置、SIDの取得方法、`usage.js` を共用する方法（共通フォルダーへ移すか、ビルド時に取り込むか）、配色の具体的な値、テスト用パイプサーバーの作り方。
