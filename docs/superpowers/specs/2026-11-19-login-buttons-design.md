# 各AIの再ログインボタン

## 目的と決めたこと

ログインが切れて使用量を取れないとき、どのAIでもボタン1つで公式ツールのログインを始められるようにする。利用者が承認した内容は次のとおり。

- Claudeにもログインボタンを付ける。Claude Code の `claude auth login` を起動する。
- Stream Deckのキーに「要ログイン」と出ているときに押すと、そのサービスのログインを始める。
- Windowsウィジェットにも、Claudeのログインボタンを付ける。
- ログインは各社の公式ツールに任せる。アプリはトークンを読み書きせず、ツールの出力も取り込まない（今のCodex・Grokと同じ）。

## 対象外

- Obsidianのツールバー。今どおり、トレイアプリの一覧を開いて、そこからログインする。
- トークンの自動更新や、ログインを使わない再取得。
- Claude Codeを npm で入れた場合の `claude.cmd`。`.exe` だけを起動する（今のCodex・Grokと同じ制限）。

## 設計

- **Claudeの「要ログイン」**：次のときに `NeedsLogin` を立てる。保存値（`usage-cache.json`）で表示を補う場合も立てる。
  - ログイン情報がない
  - トークンの期限が切れている
  - 取得先が HTTP 401 を返した

  通信の失敗、取得制限（429）、アクセス拒否（403）では立てない。
- **起動するもの**：`claude.exe` を `auth login --claudeai` の引数で起動する。シェルは使わず、新しいウィンドウで開く。作業フォルダーは利用者のフォルダーにする。
  - 探す順は、`%USERPROFILE%\.local\bin\claude.exe`（公式のインストーラーが置く場所）が先で、次に PATH のうちドライブ名から始まる絶対パスだけ。
  - 見つからなければ「Claude CLI が見つかりません」と表示する。
- **トレイアプリ**：
  - 一覧の「ログイン」ボタンと、右クリックメニューの「ログイン」に Claude を加える。
  - 起動引数 `--login-claude` を加える。すでに起動している場合は、起動中のアプリにログインを依頼する。
- **ウィジェット**：Claudeが要ログインのとき「Claude ログイン」ボタンを出す。ネイティブのプロバイダー（`widgets/Provider.cpp`）に、`login-claude` の処理を加える。
- **Stream Deck**：
  - キーが要ログインの状態で短く押すと、トレイアプリを `--login-<サービス名>` で起動する（場所の決め方は今の起動と同じ）。
  - 長押しは今どおり色の切り替え。
  - 起動できなければ「アプリの場所を設定」と表示する。
  - 起動時に渡せる引数は、`--login-claude`、`--login-codex`、`--login-grok` だけに限る。
  - プラグインの版を 1.1.2 に上げる（同じ版番号ではStream Deckが更新しないため）。
- **文書**：README、データ取得仕様、プライバシー、Stream Deck・ウィジェットのガイドの、ログインの説明を直す。

## 失敗とみなすこと

- 401などで認証が切れているのに、Claudeのログインボタンが出ない。
- 通信エラーや429だけで、ログインボタンが出る。
- PATH の相対パスや任意の文字列から、ファイルを実行する。プラグインが、決めた3つ以外の引数でトレイアプリを起動する。
- ログインツールの出力やトークンを、アプリが保存・表示する。
