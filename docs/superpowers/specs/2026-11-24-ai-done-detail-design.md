# AI の完了の記録に中身を入れる（頼んだこと・できたこと・成果物）

前の版: `docs/superpowers/specs/2026-11-23-now-doing-window-v2-design.md` の「AI の完了を日中ログへ」。この文書は、そこを置き換える部分だけを書く。

## 目的

トレイアプリが日中ログに書く 🤖 の行は、今は `[09:07]` と `🤖 Claude 完了: 進捗確認` の2行だけで、何をしたのかが分からない。夜の振り返り（`/review`）で読み返したときに、**何を頼んで、何ができて、成果物は何か**が分かる記録にする。見た目は、日誌の「ログ記録規約」の形（時刻の幅・太字の題・畳める詳細）にそろえる。

## 利用者が決めたこと（2026-11-24）

- 分かればいいのは「何を頼んで、何ができたか、成果物」。
- 作り方は A: トレイアプリが、PC の中にある Claude Code と Codex の会話の記録を読む（通信はしない）。
- 選ばなかったもの: B（Claude Code のフックや Codex の通知の設定で、AI 側から日誌に書かせる。ツールごとに設定が要り、トレイアプリの「除くフォルダー」「日誌を打っている最中は待つ」を二重に作ることになる）、C（AI に要約させる。作業のたびに通信と料金が要り、このアプリの「新しい通信をしない」に反する）。

## 言葉

| 言葉 | 意味 |
|---|---|
| 完了 | 対応待ちの一覧で、セッション（Claude Code）・スレッド（Codex）が「作業中」から「終わった」に変わったこと（今と同じ） |
| 依頼 | 利用者がそのセッション・スレッドに送った文。AI どうしのやり取り・ツールの結果・予定のタスクや定期の見回りが自分で始めた作業は含めない |
| 利用者の作業 | 依頼で始まり、完了で終わった1回分（Claude Code の1ターン・Codex の1ターン） |
| ひと続きの作業 | 同じセッション・スレッドで、利用者の作業が終わってから10分以内に次の依頼が来た間の、利用者の作業のつながり（2026-11-24 利用者が10分を選んだ。ログ記録規約の30分より短いのは、夜の振り返りの直前の作業を入れるため） |
| 詳細を読む設定 | `now_doing_ai_done_detail=on`。会話の記録を読むのは、これがオンのときだけ。この文書の新しい書き方・まとめ方は、オンのときだけ使う |

## 目標・対象外・避けること

- 目標:
  - 1つのひと続きの作業を、日中ログの1つの記録にする。1行目は時刻の幅、2行目は太字の題、その下に畳める詳細。
  - 詳細に、頼んだこと（依頼の1行目）・できたこと（最後の返事の初めの数行）・成果物（その間のコミット）を書く。
  - 会話を読むのは、詳細を読む設定をオンにしたときだけ。初めはオフ（公開しているアプリなので）。
  - オフのときは、今の書き方（`[HH:MM]` と `🤖 Claude 完了: <名前>` の2行・2分まとめる・30分に1回）のまま変えない。新しい書き方は、依頼を見分けるために会話の記録を開く必要があるため（下の「決め方」）。
- 対象外（今回）: AI による要約、コミット以外の成果物（作ったファイルの一覧など）、Claude Desktop のふつうのチャット（Claude Code ではないもの）、過去の分の書き直し、窓の「今日の記録」への表示。
- 避けること:
  - 通信すること。会話の記録を保存したり、日誌以外へ書いたりすること。
  - 詳細を読む設定がオフのときに、会話の記録のファイルを開くこと（開くことすらしない）。
  - 除くフォルダー（`now_doing_ai_done_exclude`）の作業の記録を読むこと（今と同じく、そもそも書かない）。
  - 日誌の1つの記録を長くしすぎること（ログ記録規約: 詳細は1記録8行以内）。

## 書く形（詳細を読む設定がオンのとき）

```
[08:52-09:07]
🤖 **Claude Code: 進捗確認**（AIUsageManager・作業 9分）
> [!info]- 詳細
> **🗣️ 頼んだこと:**
> - 依頼の1行目（最大3件。それより多いときは、3件目の後ろに「（ほか N件）」）
>
> **🤖 Claude の処理・出力:**
> - 最後の返事の初めの行（最大3行）
> - 📦 成果物: コミット 2件（`b44600f` Draw the buttons again… ／ `70e7a12` Say that the text went…）
```

- 1行目: ひと続きの作業の、最初の依頼の時刻から最後の完了の時刻まで。同じ分なら `[09:07]`。日中ログの中の位置は、最初の依頼の時刻で決める（窓の記録と同じ決め方）。
- 2行目: `🤖 **<アプリ>: <名前>**（<プロジェクト>・作業 <N>分）`。アプリは `Claude Code` か `Codex`。名前は対応待ちの一覧に出している名前（セッションの題、なければプロジェクト）。名前とプロジェクトが同じなら、かっこの中はプロジェクトを省いて `（作業 <N>分）`。
- 作業 N分は、AI が実際に動いていた時間の合計（各ターンの依頼から返事まで。Codex は `task_complete` の `duration_ms`、Claude Code は依頼の時刻からそのターンの最後の返事の時刻まで）。1行目の幅は待っていた時間も含むので、こちらとは別に書く（決めたこと）。1分未満は「作業 1分未満」。
- 処理・出力の見出しは、アプリに合わせて `🤖 Claude の処理・出力` か `🤖 Codex の処理・出力`。
- コミットがなければ 📦 の行は書かない。
- 詳細の行数（ログ記録規約: 詳細は8行以内）: `> [!info]- 詳細` の行と、間の空行 `>` は数えない。見出し2行＋依頼＋返事＋📦 で8行まで。超えるときは返事の行を後ろから減らす（1行は残す）。依頼は1件以上残す（決めたこと）。

### 写す文の整え方（決めたこと）

依頼・返事・コミットの題を日誌に写すときは、Obsidian のタグ・リンク・見出しにならないように整える。
- 改行・タブ・制御文字は空白1つ。1つ100文字まで（長いと「…」）。
- 返事の「初めの行」は、空行・見出し（`#` で始まる）・コードの枠（```` ``` ````）・表（`|` で始まる）・区切り線の行を飛ばして数える。行の頭の `- `・`* `・`> `・番号付きの `1. ` は外す。
- `[[A|B]]` は B、`[[A]]` は A、`![[A]]` は外す。`**` と `` ` `` は外す。
- `#` は全角の `＃` にする（タグにしないため）。

## 決め方

### ひと続きの作業のまとめ方（オンのとき。今の「2分まとめる」「30分に1回」の代わり）

- セッション・スレッドごとに、利用者の作業の完了を集める。最後の完了から10分たっても次の依頼が来なかったら、そのひと続きの作業を1つの記録として書く。記録が日誌に入るのは、作業が終わってから約10分後（今は約2分後）。
- 利用者の作業かどうか（決めたこと: 予定のタスク・定期の見回り・ほかのエージェントからの頼みで AI が自分で動いた作業は記録しない。依頼がないので「何を頼んだか」が書けないため）:
  - Claude Code: そのターンの始まりの記録の `turnOrigin` が `human` なら利用者の作業。`peer`・`task_notification`・`host_synthetic`・`sdk` だけで始まったターンは数えない（ひと続きの作業を延ばしもしない）。
  - Codex: そのターンの `task_started` の `turn_trigger` が利用者の入力（`composer` など）なら利用者の作業。`automation_heartbeat_scheduled` のような自動のものは数えない。
- Codex のヘルパーのスレッド（`session_meta` の `source` が `subagent` のもの。レビューなど）は記録しない（決めたこと: 中の依頼は Codex が書いた文で、利用者の依頼ではないため）。これはオフのときの今の書き方にも当てはめる（11/23 に `Codex「A」・Codex「A」` と同じ名前が並んだのは、このスレッドが別々に数えられたためと考えられる）。オフのときに変えるのはここだけ。
- 別々のセッション・スレッドは、同じ時間でも別々の記録にする（中身が別なので）。
- 除くフォルダー・日誌が直前10秒以内に変わっていたら10秒おきに待ち直す・5分で諦める・日誌がなければ書かない・通知しない・書いたあとのスクリプトは実行しない・`ai-done-last.md` に控え、は今と同じ。
- トレイアプリが終わるとき（トレイの「終了」・Windows のサインアウト・シャットダウン。Windows が知らせる `SessionEnding` を含む）に、まだ書いていないひと続きの作業があれば、10分を待たずにその場で書く（2026-11-24 利用者が選んだ）。このときは「日誌が直前10秒以内に変わっていたら待つ」をせず、すぐ書く。Windows の終わりを長く止めないよう、書く処理全体で5秒まで（超えた分は書かない）。

### 依頼と返事の取り方（詳細を読む設定がオンのときだけ）

- Claude Code: `~/.claude/projects/<フォルダー>/<セッションID>.jsonl`（どのフォルダーかはセッションIDのファイル名で探す）を、末尾から読む。
  - 依頼: `type` が `user` で、`turnOrigin` が `human` の記録の文。時刻（`timestamp`）がひと続きの作業の範囲のものだけ。`isSidechain` が真のもの（ヘルパーのエージェント）、文が `<` で始まるもの（コマンドやシステムの印）は除く。
  - 返事: 範囲の中で最後の、`type` が `assistant` で `isSidechain` が偽の記録の、`text` の部分。
- Codex: スレッドの記録のファイル（今も対応待ちで読んでいるもの）を、末尾から読む。
  - 依頼: `response_item` の `message` で `role` が `user` のものの文（`<` で始まるものは除く）。
  - 返事: 最後の `event_msg` の `task_complete` の `last_agent_message`。始まりの時刻は `task_started` の `started_at`。
- 読む量の上限: 末尾から20000行まで、または範囲より前の時刻の記録に来たところまで。（2026-11-24 作るときに直した: 1ターンでツールの記録が数千行になるため）1つの記録が1 MiB を超えたら飛ばす。
- 記録の形は公開された決まりではない。読めないとき・形が違うときは、その項目を書かずに、オフのときと同じ形で書く（エラーで書くのをやめない）。

### コミットの取り方（詳細を読む設定がオンのときだけ）

（2026-11-24 作るときに直した: はじめ「オン・オフとも」と書いたが、オフのときは今の書き方のまま変えないため、オンのときだけにした）


- 作業フォルダーが Git の中（`.git` がフォルダーかファイルで在る）なら、`git -C <作業フォルダー> log --since=<始まり> --until=<終わり> --format=%h %s -n 6` を、シェルを通さず・窓を出さず・5秒の上限で実行する。5件まで書き、6件目があれば「ほか」と書く。
- git がない・失敗した・時間切れのときは 📦 を書かない。

### 設定

| キー | 中身 | ないとき |
|---|---|---|
| `now_doing_ai_done` | `on` で AI の完了を書く（今と同じ） | 書かない |
| `now_doing_ai_done_detail` | `on` で、この文書の書き方（依頼・返事・成果物）にする | 会話は読まない（今の2行の書き方のまま） |
| `now_doing_ai_done_exclude` | 除く作業フォルダー（今と同じ） | 除かない |

## テスト

- Claude Code の記録の読み取り（`turnOrigin` が `human` だけ・`isSidechain` を除く・`<` で始まる文を除く・範囲の外を除く・最後の返事の `text` だけ・壊れた行は飛ばす）

- コミットの取り方（作業用の小さな Git リポジトリを作って、範囲の中と外のコミット・Git でないフォルダー）
