# 「いまやってること」キー（Stream Deck から日誌に1行書く）

## 目的

作業の途中で「いま何をしているか」を書き残したいときに、日誌のファイルを開かなくて済むようにする。Stream Deck のキーを押すと小さな入力の窓が開き、入れた1行がその日の日誌の日中ログに時刻付きで入る。日中ログは夜の振り返り（Claude Code の `/review`）が読むので、書いた記録がそのまま振り返りの材料になる。

## 利用者が決めたこと（2026-11-22）

- Stream Deck に「いまやってること」キーを足す。押すと入力の窓が開き、文字か声（Windows の音声入力 Win＋H）で入れる。
- 入れた内容は、その日の日誌の日中ログに `[HH:MM] 📝 …` の1行で入る。
- 読むのは日誌だけ、書くのは日中ログの1行だけ。**画面とキー入力は見ない**（仕事の画面に他社のデータが映るため。操作を全部記録する道具にはしない）。
- まず最小版を作り、2026-11-24〜11-28 に実際に使う。「リマインダー」キー（日誌のまだ終わっていない項目を表示する）は今回は作らない。

## 言葉

| 言葉 | 意味 |
|---|---|
| 日誌 | Obsidian の保管庫にある、1日1ファイルの Markdown（例: `…\2026-11-23 - 日誌.md`） |
| 日中ログ | 日誌の中の `## 📝 日中ログ` の見出しの次の行から、次の `## ` の見出し（または終わりの目印の行）の手前まで |
| 記録の行 | 日中ログの中で、行頭が `[HH:MM]` か `[HH:MM-HH:MM]` の行。その行から次の記録の行の手前までを1つの記録とみなす |
| 入力の窓 | キーを押すと開く、1行だけ入れられる小さな窓 |

## 目標・対象外・避けること

- 目標: キーを押し、文字か声で1行入れて Enter を押すと、日誌の日中ログの時刻順の位置に `[HH:MM] 📝 …` が入る。クリックせずにすぐ入力を始められる。
- 対象外（今回）: リマインダーのキー、日誌の内容をキーに表示すること、書いた記録の修正・削除、日誌がないときに新しく作ること、トレイ・Obsidian のプラグイン・Windows ウィジェットへの表示、Stream Deck + のダイヤル。
- 避けること:
  - 画面・キー入力・クリップボード・ほかのアプリの中身を読むこと。読むのは入力の窓に入れられた文字と日誌のファイルだけ。
  - 日中ログに1行足す以外に日誌を変えること（ほかの行の空白・改行・文字コードも変えない）。
  - 新しい通信。この機能はすべてこの PC の中で完結する。
  - 入れた文字を日誌以外の場所に残すこと。例外は下の「書く前の控え」だけ。
  - 日誌の場所をコードや文書に書くこと。場所は `settings.ini`（Git に入らない）で決める。

## 作り方の案

`--login-claude` などと同じく、プラグインが決まった引数でアプリを起動する形にする。

- **A（選ぶ）: `AIUsageManager.exe --now-doing` を、トレイとは別の短い処理として起動する**（`--obsidian-data` と同じ扱い）。窓を開き、書いたら終わる。トレイアプリが起動していなくても使える。トレイ側の変更がいらない。
- B: 起動中のトレイアプリに合図（`EventWaitHandle`）を送り、トレイが窓を開く。トレイが止まっていると使えず、合図が1つ増える。
- A を選ぶ理由: 変更が小さく、トレイアプリが止まっていても記録できる。

## 設計

### Stream Deck のキー

- `streamdeck/manifest.json` に動作を1つ足す: UUID `io.github.genkis3zu.aiusagemanager.nowdoing`、名前「いまやってること」、説明「押すと小さな窓を開き、入れた1行を今日の日誌の日中ログに書きます」。`Version` を上げる（今は 1.4.0.0）。
- キーの表示は固定（「📝」と「いま」「やってること」）。使用量の値は出さない。
- 押したら（`keyUp`）、`resolveAppPath` で見つけたアプリを `--now-doing` で起動する。
  - トレイアプリにつながっていない（未接続・起動中）ときも、トレイは起動せず、そのまま `--now-doing` で起動する。今の `press()` の「起動中は無視」「未接続ならトレイを起動」の分岐より前で扱う。
  - 起動できたら ✓ を出す（`streamdeck.js` に `showOk(context)` を足す）。アプリが見つからない・起動できないときは、今と同じく「アプリの場所を設定」を出す。
  - 長押しも同じ動き。
- `streamdeck/src/location.js` の `APP_ARGUMENTS` に `--now-doing` を足す。決めた引数しか渡せない決まりは変えない。

### アプリ（`--now-doing`）

- `Program.Main` の先頭（トレイの重複起動を防ぐ Mutex より前）で `--now-doing` を見て、入力の窓を開く処理へ分ける。トレイアプリの起動・表示には触らない。
- 入力の窓は同時に1つだけ。`Local\AIUsageManager.NowDoing.<SID>` の Mutex を取れなければ、何もせずに終わる（2回押しても窓は増えない）。
- 記録の時刻は**キーを押して窓が開いた時刻**（分まで）。窓を開いたまま日付が変わっても、開いた日の日誌に書く。

### 入力の窓

- 小さな窓（目安 幅420×高さ120）。マウスのある画面の中央に出す。いちばん手前（`TopMost`）に出して `Activate()` し、入力欄にカーソルを置く。
- 中身は、見出しの1行（`11:05 の記録　Enter で日誌へ ／ Esc でやめる`）と、1行の入力欄だけ。日誌の内容は表示しない。
- 入力欄では日本語入力（IME）と Windows の音声入力（Win＋H）が使えること。普通の `TextBox` で足りるはず（実機で確かめる）。
- 最大200文字。
- Enter: 前後の空白を消し、改行とタブは空白1つにする。空なら何も書かずに閉じる。空でなければ日誌に書き、書けたら閉じる。
- Esc・閉じるボタン: 何も書かずに閉じる。
- 書けなかったとき: 窓を閉じず、入れた文字を残したまま、見出しの行に赤で理由を出す（下の表）。もう一度 Enter で書き直せる。

### 日誌への書き込み

**設定（`settings.ini`・アプリと同じフォルダー・Git に入らない）**

| キー | 中身 | ないとき |
|---|---|---|
| `now_doing_note` | 日誌のファイルの場所。`{` `}` の中は日付の書式（.NET の日付の書式・`InvariantCulture`）で置き換える。例: `C:\Notes\{yyyy}年_日誌\{yyyy-MM-dd} - 日誌.md` | 書かずに「settings.ini に now_doing_note がありません」 |
| `now_doing_heading` | 日中ログの見出しの行（行全体が一致） | `## 📝 日中ログ` |
| `now_doing_before` | 日中ログの終わりの目印。この文字で始まる行の手前より後ろには入れない | 指定なし（次の `## ` の見出しが終わり） |

- 今の `ThemeSettings.Save`（`src/Theme.cs`）は、テーマ・通知・対応待ちの3行だけで `settings.ini` を書き直すので、上の3行が消える。保存するときは、知らないキーの行をそのまま残すように直す。

**入れる位置**

1. 書く直前に日誌を読む（窓を開いたときではない。窓を開いている間に Obsidian や Claude Code が日誌を書き換えることがあるため）。
2. 見出しの行を探す。日中ログはその次の行から、次の `## ` で始まる行か、`now_doing_before` で始まる行の、先に来る方の手前まで。
3. 日中ログの中の記録の行（`^\[(\d{2}):(\d{2})`）のうち、開始の時刻が**記録の時刻より後**のものを上から探し、最初に見つかった行の手前に入れる。同じ時刻の記録がすでにあれば、その後ろになる。
4. 後の時刻の記録がなければ、日中ログの終わりの手前に入れる（終わりの直前に続く空行より前）。
5. 入れる中身は `[HH:MM] 📝 <入れた文字>` の1行。前後の空行がちょうど1つずつになるようにする（すでにあれば足さない）。

例（11:05 に「見積の表を直している」と入れた）:

```
[10:00-10:30]
🏋️ ジム …

[11:05] 📝 見積の表を直している

[12:00-13:00]
昼食。…
```

**ファイルの扱い**

- UTF-8 で読む。UTF-8 として正しくないときは書かない。
- BOM の有無と改行（LF か CRLF）は、読んだファイルに合わせる。足した行と空行以外は1バイトも変えない。
- 同じファイルに上書きする（一時ファイルを作って名前を付け替える方法は使わない。日誌のフォルダーはクラウドと同期していて、名前の付け替えが別のファイルとして扱われることがあるため）。
- 書く前の控え: 上書きの直前の中身を `%LOCALAPPDATA%\AIUsageManager\now-doing-last.md` に1つだけ残す（次に書くときに置き換える）。書き込みの途中で失敗したときに戻すため。
- ほかのアプリが書いている最中で開けないときは、0.3秒おきに3回まで試す。それでも開けなければ書かない。

**書けなかったときの表示**

| 場合 | 窓に出す文 |
|---|---|
| `now_doing_note` がない | settings.ini に now_doing_note がありません |
| 日誌のファイルがない | 今日の日誌がまだありません |
| 見出しがない | 「## 📝 日中ログ」が見つかりません（設定した見出しの文を出す） |
| UTF-8 として読めない | 日誌の文字コードを読めません |
| 開けない・書けない | 日誌が使用中です。もう一度 Enter を押してください |

## テスト

- **Tests.exe（画面なし）**: 入れる位置の計算は窓と分け、「日誌の文字列・時刻・入れた文字・設定」から「新しい文字列か、書けない理由」を返す関数にする。確かめること:
  - 後の時刻の記録の手前に入る ／ 同じ時刻の記録の後ろに入る ／ `[HH:MM-HH:MM]` の記録も開始の時刻で比べる
  - 後の記録がないとき `now_doing_before` の行の手前に入る ／ 指定がないとき次の `## ` の手前に入る ／ 日中ログがファイルの最後まで続くときは最後に入る
  - 引用（行頭が `>`）の中の `[HH:MM]` と、`[[` で始まる行は記録の行とみなさない
  - 前後の空行がちょうど1つずつになる
  - LF・CRLF・BOM あり／なしがそのまま残る
  - 見出しがない・`now_doing_note` がないときは書かない
  - `{yyyy}` `{yyyy-MM-dd}` の置き換え
  - 改行・タブが空白になり、200文字で切れる
  - テーマ・通知・対応待ちの設定を保存しても、`now_doing_` で始まる行が残る
- **Stream Deck のテスト（`streamdeck/tests`）**: 新しいキーを押すと `--now-doing` で起動する ／ 未接続・起動中でも起動し、トレイは起動しない ／ アプリが見つからないと「アプリの場所を設定」 ／ `APP_ARGUMENTS` に `--now-doing` がある ／ `manifest.json` に新しい動作がある。
- `build.ps1` と Stream Deck のテストがすべて通ること。
- `docs/streamdeck-guide.md` に「いまやってること」キーの節を足す（設定の3つのキーも書く）。

## 実機での確認（作ったあと・利用者と一緒に）

1. Obsidian を前に出した状態でキーを押す → 窓が前に出て、クリックせずに文字を打てる。
2. 「テスト」と入れて Enter → 今日の日誌の日中ログの正しい位置に `[HH:MM] 📝 テスト` が入り、Obsidian の画面にも出る。
3. 別のアプリ（ブラウザ・仕事で使う全画面の画面）を前にした状態でも 1 と同じになる。
4. Win＋H で声で入れて Enter → 同じく入る。
5. 2回続けて押しても窓は1つ。Esc では何も書かれない。
6. 日誌がない日付を指す設定にして押す → 「今日の日誌がまだありません」が出て、何も書かれない。

## 未確認（作るときに確かめる）

- **窓が手前に出て入力を受け取れるか。** Windows は、利用者が操作していないアプリが前に出ることを制限している。Stream Deck のキーから起動したアプリが前に出られるかは未確認。出られないときは、キー入力をまねるなどの回避策は使わずに止まって報告する（その場合は、窓を一度クリックしてから入れる形で使う）。
- Windows の音声入力（Win＋H）が、この窓の入力欄で使えるか。
- Obsidian が日誌を開いているときに外から書いても、Obsidian 側の表示が書き換わり、入れた行が消えないか（Obsidian は外からの変更を読み直す。Obsidian で日誌を打っている最中にキーを使うことは少ない想定）。

## 変更（2026-11-23・実機で使ったあとの利用者の指示）

上の「`[HH:MM] 📝 …` の1行」と「窓は日誌の中身を出さない」は、次のとおりに変えた。

- 書く形を、日誌のほかの記録と同じ2行（1行目 `[HH:MM]`、2行目 `📝 …`）にした。窓に出す記録の一覧は、前の1行の形も読む。
- 窓の上に、書き込む日誌のページ名・見出し・フォルダーを出す。窓を開いたときに読んだ settings.ini を、表示と書き込みの両方に使う（表示と違うページに書かないため）。
- 窓を開いたときに日誌を読み、書けない理由があればその場で赤で出す。
- 窓の下に、その日の日中ログにある 📝 の記録を新しいものから6件まで出す。
- 窓をタイトルバーのない形にし、トレイの窓と同じ色・角の丸みにした。空いているところをドラッグすると動かせる。
- `now_doing_claudian=on` のとき、Ctrl+Enter で日誌に書いたあと、同じ文を Claudian のチャットに送る。窓は文と1回だけ使える合言葉を `%LOCALAPPDATA%\AIUsageManager\claudian-message.json` に置き、合言葉だけを入れた `obsidian://ai-usage-manager-claudian` のリンクを開く。AI Usage Manager の Obsidian プラグインが、合言葉が合うときだけ文を受け取り、Claudian の入力と同じ部分（`inputController.sendMessage`）で送る。Claudian に公開の受け口がないため、Claudian の更新で送れなくなることがある。通信は増えない（Claudian が送るのは Claudian 自身の通信）。
- `now_doing_hotkey`（例: `Ctrl+Alt+N`）を書くと、トレイアプリがそのショートカットキーを RegisterHotKey で登録し、押されたら `--now-doing` で窓を開く（Stream Deck のキーと同じ形）。トレイアプリは、窓の処理が手前に出られるように AllowSetForegroundWindow で許す。
- トレイの「使用量」の窓を、ボタン・サービスの行・対応待ちの項目以外のところをドラッグして動かせるようにした（次に開くときは、いままでどおりトレイの近くに出る）。
