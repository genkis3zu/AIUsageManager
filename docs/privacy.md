# プライバシーとデータの扱い

## 読み取り対象

現在のWindowsユーザーのプロファイル内から、次のファイルだけを利用します。カスタムホームディレクトリには対応していません。

| パス（`%USERPROFILE%` からの相対） | 用途 |
|---|---|
| `.codex/sessions/**/*.jsonl` | Codexの週使用量・観測時刻 |
| `.codex/auth.json` | Codexの既存ChatGPTログインによる認証 |
| `.grok/logs/unified.jsonl` | Grokの成功応答でプラン名が欠ける場合の補足（使用率には使わない） |
| `.grok/auth.json` | Grokの既存ログインによる認証 |
| `.claude/.credentials.json` | Claude Codeの既存ログインによる認証 |
| `.claude/usage-cache.json` | 存在する場合だけ、Claude使用量の代替情報 |

AI Usage Managerの取得処理は、これらのファイルへの書き込み、トークン更新、CLI設定変更をしません。会話を含むログの末尾を読み取りますが、パーサーが取り出すのは使用量と関連する表示項目です。

## 通信

| サービス | HTTPSの宛先・メソッド | 認証 |
|---|---|---|
| Claude | GET `api.anthropic.com/api/oauth/usage` | 既存ログインのBearerトークン |
| Grok | GET `cli-chat-proxy.grok.com/v1/billing?format=credits` | 既存ログインのBearerトークンと、存在すればユーザーIDヘッダー |
| Grokの使用率補完 | 読取専用POST `grok.com/grok_api_v2.GrokBuildBilling/GetGrokCreditsConfig` | 上記と同じBearerトークン（Cookieなし） |
| Codex | GET `chatgpt.com/backend-api/wham/usage` | 既存ChatGPTログインのBearerトークンと、存在すればアカウントIDヘッダー |

リダイレクトとCookieは無効、証明書はWindows標準検証、タイムアウトは15秒、応答上限は1 MiBです。テレメトリー、分析SDK、独自バックエンド、自動更新確認はありません。サービス側は通常の認証リクエストに伴う情報を受け取ります。

Grokの追加照会は、有効な現在の週が返り使用率だけが省略された場合に限り、最大6秒で1回実行します。固定の使用量照会メッセージを送り、購入・自動チャージ・クレジットの利用・設定変更は行いません。応答はメモリで検証し、使用率だけを同じ週の表示へ反映します。

## ユーザーが開始するログイン

Codex・Grokの「ログイン」ボタンは、インストール済みの公式CLIを起動します。引数は `codex.exe login` または `grok.exe login --oauth` に固定し、認証情報をコマンド引数に含めません。CLIの出力をキャプチャ・保存しません。既知のユーザー別インストール先と絶対パスのPATHから実行ファイルを探し、シェル文字列として実行しません。

認証中は公式CLIのウィンドウとブラウザが開きます。認証ファイルの保存・更新やOAuth通信は公式CLIが行います。AI Usage Manager自身はトークンを保存せず、CLI終了後に上記ファイルを読み直します。定期更新がログインを自動起動することはありません。

## 保存と表示

- 認証情報は取得のために一時的にメモリ上で使用します。
- 急増・到達予測のため、各枠の直近30分・最大120件の割合と取得時刻をメモリ上だけに保持します。使用履歴や認証情報をアプリ独自のファイルに保存しません。履歴は終了時に消えます。
- トークン、認証ファイル、生レスポンス、例外本文をログや画面に出力しません。
- プランは表示を許可した名前だけに変換し、不明な文字列をそのまま表示しません。
- アプリ自身が保存するのは、exeの横の `settings.ini` にあるテーマと通知の選択だけです。保存時は `settings.ini.tmp` を使います。
- Windowsのアプリテーマ設定を読み取りますが、変更しません。
- Windows通知にはサービス名・使用枠・割合・リセットや到達予測の時刻を表示します。認証情報は含めません。Windows側の通知履歴に表示内容が残る場合があります。

開発用 `Diagnostics.exe --live` は、プラン・使用率・取得時刻をコンソールと画像に出力します。Release ZIPには診断ツールを含めません。開発時のライブ出力も個人データとして扱ってください。

## Windowsウィジェット

オプションのネイティブプロバイダーは、同じパッケージ内のアプリを `--widget-data` で一時起動します。アプリは上記と同じ読取処理を行い、表示用のプラン・使用率・時刻・状態だけを匿名パイプで渡します。認証情報や生レスポンスは渡しません。画像はカード内に埋め込み、画像取得の外部通信はありません。

この起動モードを手動で実行して標準出力を保存すると、そのファイルに使用量が含まれます。出力は公開しないでください。`--widget-sample` は架空値だけを使います。

Windowsのウィジェットホストは表示カードを保存する場合があります。これはアプリ独自の履歴保存とは別です。ウィジェットのピン留め状態や登録情報もWindowsが管理します。インストールスクリプトはアプリ専用フォルダーへ配布ファイルをコピーし、現在のユーザーに登録します。資格情報やCLIファイルはコピーしません。

## Obsidianプラグイン

オプションのプラグインは常駐アプリのメモリ上の表示データを15秒ごとに読み取ります。認証ファイル、CLIログ、ノート本文を読み取らず、ノートやテンプレートに書き込みません。サービスへの追加の問い合わせや独自のWindows通知も行いません。

連携は現在のWindowsユーザーだけを許可し、ネットワークログオンを拒否する名前付きパイプを使います。ローカルHTTPサーバーは起動しません。`--obsidian-data` はプラン・使用率・取得／リセット時刻・警告など、明示的に選んだ表示項目だけを返します。認証情報・アカウントID・生レスポンスは含めません。手動でこの出力を保存した場合は使用量を含むため公開しないでください。

プラグイン設定として、表示サイズと指定したアプリの絶対パスだけをVaultの `.obsidian/plugins/ai-usage-manager/data.json` に保存します。使用量の履歴は保存しません。Vault設定の同期を使う場合、このパスも同期対象になる可能性があります。取得データはObsidianプロセス内のメモリに存在します。

プラグインから起動する実行ファイルはドライブを指定したローカル絶対パスに限定し、引数は固定、シェルは介在しません。通信には時間と出力量の上限を設けます。無効化すると定期読み取りを停止し、未完了の補助プロセスと自身の画面要素を解放します。
