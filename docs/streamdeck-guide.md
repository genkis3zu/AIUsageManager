# Stream Deckへの表示（1.1開発版）

Stream Deckのキーに、Claude・Codex・Grokの使用量と、AnthropicとOpenAIの障害情報を表示します。表示する値は、トレイアプリが取得したものを受け取るだけです。**このプラグイン自身は、AIサービスにも障害情報ページにも問い合わせません。**

## 表示と操作

キーは5種類です。Stream Deckアプリの右側の一覧にある「AI Usage Manager」から、ボタンへドラッグして置きます。

| キー | 表示するもの |
|---|---|
| Claude 使用量 | 取得先が返す枠（例：Ultraは週とFable、Maxは5時間・週・Fable） |
| Codex 使用量 | 週（Plusなどは5時間も） |
| Grok 使用量 | 週 |
| AIの状況 | AnthropicとOpenAIの障害情報と、週の使用枠のリセット（[下記](#aiの状況キー)） |
| 対応待ち | Claude CodeとCodexのうち、返事を待っているもの（[下記](#対応待ちキー)） |

1つのキーに描く枠は3つまでです。4つ目以降はキーに描きません（トレイアプリの一覧では確認できます）。

使用量のキーは、次の設定を変えられます。

- **表示スタイル**：リング／縦バー／横バー。リセットまでの時間は、キーの右下に大きめに1つだけ表示します。枠ごとにリセット時刻が違うとき（例：5時間と週）は、各枠の下（横バーで3本のときは枠の名前の横）に表示します。横バーは、本数が少ないほど太く、数字を大きく描きます。
- **数値**：使用率（使った割合）／残り。
- **リセットまでの時間**：表示する／しない。
- **色**：緑・オレンジ・青・紫・ピンク・グレー。
- 最初の設定は、縦バー・使用率・リセットまでの時間を表示、色はClaudeがオレンジ、Codex・Grokが緑です。

| 操作 | 動作 |
|---|---|
| 短く押す | 表示スタイルを切り替える。「要ログイン」のキーでは、そのサービスのログインを始める |
| 0.5秒より長く押す | 色を切り替える |
| キーを選んで下の設定画面を開く | 上の4項目と、トレイアプリの場所を変更する |

キーに出る言葉の意味は次のとおりです。

| 表示 | 意味 |
|---|---|
| 読み込み中 | プラグインが起動した直後です |
| 未取得 | 値がありません。取得済みの0%とは区別します |
| 色を落とした値と「保存された値」など | 15分以上前の値、または取得に失敗した値です。現在の値としては扱いません |
| 色を落とした値と「期限経過」 | リセット時刻を過ぎた枠の、リセット前の値です。トレイアプリの次の取得で新しい値に変わります |
| 黄色・赤の値 | 上限が近い状態です。90%以上で黄色、95%以上で赤になります。トレイアプリの予測で、リセット前に上限に届く見込みのときも黄色になります |
| 要ログイン | ログインが必要です。キーを短く押すと、トレイアプリがそのサービスの公式ログイン（ブラウザでの認証）を始めます |
| 未接続 | トレイアプリが起動していません |
| 起動中 | トレイアプリを起動し、値を待っています（Stream Deckの起動時、または「未接続」のキーを押したとき） |

### 「AIの状況」キー

トレイアプリが5分ごとに読む、AnthropicとOpenAIの障害情報を表示します。会社ごとに1行ずつ、「Claude 正常」「OpenAI 一部不調」のように表示します。読み方は [データ取得仕様](data-sources.md#障害情報aiの状況) を参照してください。

| 行の右側 | 意味 |
|---|---|
| 正常（緑） | その会社の障害情報に、問題は出ていません |
| 一部不調（黄） | 一部の障害・性能低下・メンテナンスが出ています |
| 障害（赤） | 重大な障害が出ています。Claudeは、claude.ai・Claude Code・Claude APIのどれかが対象です |
| 確認できず（灰色） | その会社の障害情報を読めませんでした。正常かどうか分かりません |

- 下の小さな文字は、一部不調・障害のときは影響を受けている項目（例：Claude Code）です。問題がないときに週の使用枠がリセットされた場合は、「Claude Fable リセット」のように緑で1時間表示します。
- 「未取得」は、障害情報をまだ受け取っていない状態です。トレイアプリの起動直後（最初の更新が終わるまで）か、障害情報に対応していない古い版のトレイアプリです。
- キーを押すと、問題が出ている会社の障害情報ページを既定のブラウザで開きます。両社に問題があるときは悪いほう（同じ程度ならAnthropic）、問題がないときはAnthropicのページです。
- 「未接続」のときは、ほかのキーと同じくトレイアプリを起動します。
- このキーには設定画面がなく、長押しにも同じ動作をします。

### 「対応待ち」キー

Claude Code（デスクトップアプリ・VS Code）とCodex（ChatGPT/Codexアプリ・VS Code）のうち、あなたの返事を待っているものの数と、いちばん長く待たせているものを表示します。読み方は [データ取得仕様](data-sources.md#対応待ちclaude-codecodex) を参照してください。

| 表示 | 意味 |
|---|---|
| 右上の数字 | 対応待ちの数 |
| AIの名前と、その下の名前 | いちばん長く待たせているもの。名前はClaudeではセッションの題名、Codexでは作業フォルダー名 |
| 質問・確認 | 待っている理由。「質問」は答えを、「確認」は操作を待っています |
| 時間（黄・赤） | 待たせている時間。10分以上で赤 |
| 対応待ちなし・完了 N件 | 待っているものがない。最近30分に終わった作業の数 |
| 確認できず・◯◯ 読めません | そのAIの記録を読めません。対応待ちがないとは言い切れない状態です |
| 未取得 | トレイアプリがまだ一覧を送っていません（起動の直後、または対応待ちに対応していない古い版） |

- キーを押すと、いちばん長く待たせているもののアプリ（Claude、ChatGPT/Codex、VS Code）を開きます。対応待ちがなく完了があるときは、いちばん新しい完了のアプリを開きます。開くアプリが決まらないもの（ほかのプログラムが動かしているClaude Codeなど）が先頭のときは、何も開きません。
- Codexの承認待ちとGrok Botは、今の版では表示されません。
- このキーには設定画面がなく、長押しにも同じ動作をします。

### 「いまやってること」キー

押すと小さな入力の窓が開き、入れた文を今日の日誌（Obsidian などの Markdown のファイル）の日中ログに、時刻付きで書きます（記録）。ほかの記録と同じく、1行目に時刻、2行目に本文の2行で書きます。

```
[15:40]
📝 入れた文
```

- 窓は、マウスのある画面の中央に、ほかの窓より手前に出ます。文字のほか、Windows の音声入力（Win＋H）でも入れられます。
- `now_doing_hotkey` を書くと、トレイアプリが動いている間は、ショートカットキー（例: `Ctrl+Alt+N`）や、Ctrl・Shift・Alt の2回押し（例: `DoubleRightAlt`、下の「2回押しで開く」）でも同じ窓を開けます。ほかのアプリが同じキーを使っているときや、書き方が違うときは、トレイアプリの起動時に通知で知らせます。書き換えたときは、トレイアプリを起動し直すと使われます。
- 窓の上に、書き込む日誌のページ名と見出し（例: `2026-11-24 - 日誌  ›  📝 日中ログ`）と、そのフォルダーを出します。書くのはこのページだけです。
- 窓を開いたときに日誌を読み、書けない理由（日誌がまだない、見出しがない など）があれば、その場で赤で出します。
- 窓の下に、その日の日中ログにある 📝 の記録を、新しいものから6件まで出します。画面の高さが足りないときは、3件まで減らします。
- 入力欄は1行の高さから始まり、行が増えると6行まで伸びます。それより多いときはスクロールします。貼り付けた文は、改行もそのまま入ります（画像は入りません）。

| キー | すること |
|---|---|
| Enter | 記録。入れた文を日中ログに書いて閉じます。複数行のときは、改行とタブを空白1つにして1行にします。200文字までです |
| Shift+Enter | 改行 |
| Ctrl+Enter | 送る（`now_doing_claudian=on` のとき。下の「Claudian に送る」）。オフのときは Enter と同じです |
| Alt+1〜Alt+9 | ボタン1〜9（下の「ボタン」） |
| Ctrl+A | 入力欄の文をすべて選ぶ |
| Esc | 何も書かずに閉じる |

- 空のまま Enter、Esc、閉じるボタン（×）では何も書かずに閉じます。窓は、空いているところをドラッグすると動かせます。
- 200文字を超えた文で Enter を押したときは、書かずに「日誌に書けるのは200文字までです」と出します。文は切らずに残します。
- 時刻は、キーを押して窓が開いた時刻（分まで）です。窓を開いたまま日付が変わっても、開いた日の日誌に書きます。
- 書く位置は、日中ログの中で、行頭が `[HH:MM]` か `[HH:MM-HH:MM]` の記録の行のうち、開始の時刻がこの記録より後のものの手前です。後の記録がなければ日中ログの終わりの手前に書きます。前後の空行はちょうど1つずつにします。コードブロック（```` ``` ```` や `~~~` で囲んだ部分）の中の行は、見出しや記録として扱いません。日誌のほかの行は変えません（文字コード、BOM、改行の種類もそのままです）。
- 書けなかったときは、窓を閉じずに理由を赤で出します。入れた文字は残るので、もう一度 Enter で書き直せます（日誌を作ったあとなら、そのまま書けます）。

| 窓に出る文 | 意味 |
|---|---|
| settings.ini に now_doing_note がありません | 日誌の場所を設定していません（下の表） |
| settings.ini の now_doing_note の書き方が違います | 場所が絶対パスでないか、`{ }` の中の日付の書式が正しくありません |
| 今日の日誌がまだありません | その日の日誌のファイルがありません。このキーは日誌を新しく作りません |
| 「## 📝 日中ログ」が見つかりません | 日誌に、設定した見出しの行がありません |
| 日誌の文字コードを読めません | 日誌が UTF-8 ではありません |
| 日誌が使用中です。もう一度 Enter を押してください | ほかのアプリが日誌を書いている最中で、開けませんでした（日誌は変えていません） |
| 書く前の控えを残せないため、書きませんでした | 下の控えのファイルを書けませんでした（日誌は変えていません） |
| 書き込みが途中で失敗しました。日誌を確かめてください（書く前の中身は now-doing-last.md） | 日誌を書き始めたあとで失敗しました。書き直しはしないので、日誌を開いて確かめ、必要なら控えから戻してください |
| 日誌に書けるのは200文字までです | Enter で書けるのは200文字までです（日誌は変えていません）。長い文は Ctrl+Enter で Claudian に送れます |
| 4000文字までです | Ctrl+Enter で送れるのは4000文字までです（日誌にも書かず、送ってもいません） |
| 日誌には書きました。Claudian には送れませんでした（Obsidian を開けません） | 日中ログの1行は書けています。Claudian には届いていません |
| 日誌には書きました。そのあとの処理に失敗しました: … | 書いたあとのスクリプトが失敗しました。日中ログの1行は書けています |
| コピーできませんでした: … | copy のボタンの命令が失敗したか、出力が空でした。クリップボードは変えていません |
| クリップボードに入れられませんでした | ほかのアプリがクリップボードを使っていて、入れられませんでした |
| settings.ini の now_doing_buttonN の書き方が違います | そのボタンの書き方が違います（そのボタンは出ません。窓の下に出ます） |
| まだのことを出せませんでした | 一覧のスクリプトが失敗しました（窓の下に出ます） |

#### Claudian に送る（Ctrl+Enter）

`now_doing_claudian=on` のときは、Ctrl+Enter で、入れた文の1行目を日中ログに書いたあと、全文を Obsidian の Claudian のチャットに送ります。ほかの AI の結果のような、複数行の長い文も送れます。AI Usage Manager の Obsidian プラグイン（1.3.0 以降）が要ります（[Obsidian のガイド](obsidian-guide.md)）。

- 日中ログには、1行目の先頭80文字を書きます。2行以上あるときは、その後ろに `（Claudian へ・N行）` を付けます（N は送った文の行数）。
- 送れる全文は4000文字までです。
- Obsidian のプラグインは、書いた日誌を今のタブで開いてから Claudian に送ります。
- 日誌に書けなかったときは送りません。Obsidian を開けなかったときは「日誌には書きました。Claudian には送れませんでした」と出し、入力欄を空にします（もう一度 Enter を押しても二重に書かないため）。

#### ボタン

`now_doing_button1`〜`now_doing_button9` を書くと、入力欄の下にボタンが番号の順に並びます（窓の幅に入らない分は次の行に回します）。名前が長いときは8文字で切ります。Alt+1〜Alt+9 でも押せます。書き方は `<名前>|<動き>:<中身>` です。

| 動き | すること | 例 |
|---|---|---|
| `text:<文>` | 入力欄にこの文を入れます（カーソルは末尾）。続きを打って Enter | `now_doing_button5=⏱️ 作業\|text:⏱️ ` |
| `record:<文>` | この文をそのまま記録します（入れて Enter を押したのと同じで、書いたあとのスクリプトも動きます） | `now_doing_button1=🚶 散歩\|record:🚶 散歩 ✅` |
| `copy:<命令>` | 命令を実行し、標準出力をクリップボードに入れて、1.5秒後に窓を閉じます。後ろに `\|open:<リンク>` を付けると、そのあとリンクを開きます。開けるのは `claude://` `codex://` `vscode://` `grokbot://` だけです | `now_doing_button7=📈 依頼文\|copy:python -X utf8 scripts\request.py\|open:claude://` |

- `text:` の後ろの空白（`⏱️ ` の空白など）も、そのまま入力欄に入ります。
- copy は、命令が失敗したときや出力が空のときは、クリップボードを変えず、リンクも開かずに理由を出します。

#### 書いたあとのスクリプト・一覧のスクリプト

日誌の決まり（どの行に ✅ を付けるか、frontmatter のどのキーに書くか、何を「まだのこと」として出すか）はアプリに持たせず、利用者のスクリプトに置きます。アプリは、`settings.ini` に書かれた命令を実行して結果を出すだけです。

| 設定 | いつ実行するか | 窓が後ろに足す引数 | 時間の上限 | 標準出力の上限 |
|---|---|---|---|---|
| `now_doing_after`（書いたあとのスクリプト） | 日中ログに書いたあと毎回（Enter・record のボタン・Ctrl+Enter） | `--note <日誌の場所> --time <HH:MM> --mode <record か send> --text <入れた文>` | 10秒 | 4096バイト・20行 |
| `now_doing_list`（一覧のスクリプト） | 窓を開いたとき | `--note <日誌の場所>` | 3秒 | 4096バイト・20行 |
| ボタンの `copy` | ボタンを押したとき | `--note <日誌の場所>` | 10秒 | 32KB |

- 命令は、実行ファイルと引数をそのまま書きます（例: `python -X utf8 "C:\Notes\scripts\after.py"`）。先頭の語が実行ファイルで、`"` で囲めば空白を含められます。シェル（cmd や PowerShell）は通さず、窓も出しません。入れた文は引数1つとして渡し、命令の文字列には埋め込みません。バッチファイル（`.bat`・`.cmd`）は使えません（Windows が cmd を通して実行し、入れた文の `&` や `%` が命令として扱われるため。窓に「バッチファイル（.bat・.cmd）は使えません」と出ます）。同じ理由で、命令の先頭に `cmd` を書くのも避けてください。
- スクリプトの作業フォルダーは `now_doing_workdir` です（書かないときはアプリのフォルダー）。
- `--text` には、窓が日中ログで先頭に付ける `📝 ` を除いた文を渡します。Ctrl+Enter（`--mode send`）のときは、日中ログに書いた1行ではなく、入れた全文を渡します。
- 標準出力は UTF-8 として読みます。終了コードが0以外のとき、時間切れのとき、起動できないとき、標準出力が上限を超えたときは失敗です。時間切れなどで止めるときは、スクリプトと、スクリプトが起動したプログラムを終わらせます。失敗の理由には、標準エラーの最初の1行を使います。
- 書いたあとのスクリプトが成功したときは、標準出力の1行目を窓に1.5秒出してから閉じます（空ならすぐ閉じます）。失敗したときは、日中ログの1行は残したまま、窓を閉じずに理由を出し、入力欄を空にします。Ctrl+Enter のときは、スクリプトが終わってから（失敗しても）Claudian に送ります。スクリプトが動いている間（10秒まで）は、窓はキーを受け付けません。
- 一覧のスクリプトの標準出力の行（空行を除いて最大5行）は、入力欄の上に「まだのこと」として出します。長い行は1行に収まるように切ります。表示だけで、押しても何も起きません。窓を閉じたときにまだ動いていれば、終わらせます。

#### 2回押しで開く

`now_doing_hotkey` に次のどれかを書くと、トレイアプリが動いている間、そのキーの2回押しで窓を開けます。

| 値 | 押すキー |
|---|---|
| `DoubleCtrl` | Ctrl を2回（左右どちらでも。1回目と2回目で左右が違ってもよい） |
| `DoubleLeftCtrl` | 左 Ctrl を2回 |
| `DoubleRightCtrl` | 右 Ctrl を2回 |
| `DoubleShift` | Shift を2回（左右どちらでも） |
| `DoubleLeftShift` | 左 Shift を2回 |
| `DoubleRightShift` | 右 Shift を2回 |
| `DoubleAlt` | Alt を2回（左右どちらでも） |
| `DoubleLeftAlt` | 左 Alt を2回 |
| `DoubleRightAlt` | 右 Alt を2回 |

- 押している時間が300ミリ秒以内で、離してから400ミリ秒以内にもう一度押した（2回目も300ミリ秒以内）ときに開きます。間にほかのキーを押したときや、Ctrl+C・Shift+A・Alt+Tab のようにほかのキーと一緒に押したときは開きません。押しっぱなしにしたときの繰り返しは、1回として数えます。
- Alt の2回押しを選んだときは、前にあるアプリにも Alt がそのまま届くので、メニューに移る・Office のキーの案内が出るなど、Alt だけを押したときの動きが起きます（2回目の Alt で元に戻ることが多いです）。
- 右 Alt を AltGr として使うキーボード配列（ドイツ語など）では、Windows が左 Ctrl も押したことにするため、`DoubleRightAlt` は働きません。日本語のキーボードでは働きます。
- PowerToys の「マウスを探す」は、既定で左 Ctrl の2回押しを使います。両方を使うと、同じ操作で両方が動きます。「マウスを探す」を使うなら、それと重ならないもの（`DoubleRightCtrl`・`DoubleShift` など）を選ぶか、PowerToys の設定で「マウスを探す」をオフにしてください。
- 2回押しは、キーボード全体の入力を受ける仕組み（`WH_KEYBOARD_LL` のフック）で見つけます。見るのは、左右の Ctrl・Shift・Alt の押し離しと時刻だけです。ほかのキーは、押されたことだけを見て、どのキーかは残しません。何も保存せず、キーはそのまま前にあるアプリに届きます（止めたり変えたりしません）。
- 2回押しで開いた窓は、Windows の決まりで前に出られないことがあります。そのときは、まずキーを送らない方法で前に出し、それでも出られないときだけ、どの機能にも割り当てられていないキー（仮想キー `0xE8`）を1つ送ってから前に出します。Stream Deck のキーや `Ctrl+Alt+N` の形のショートカットキーで開いたときは送りません。開発に使った PC（Windows 11）では、右 Alt の2回押しで開いた窓は、キーを送らない方法（`AttachThreadInput`）で前に出ました。
- 管理者として動いているアプリが前にあるときは、Windows の決まりで2回押しが届きません。
- キーボードの入力を受けられなかったときは、トレイアプリの起動時に通知で知らせます。

#### AI の完了を日中ログに残す

`now_doing_ai_done=on` のときは、トレイアプリが、対応待ちの一覧で新しく「完了」になった Claude Code・Codex の作業を、窓の記録と同じ形で日中ログに書きます。

```
[15:42]
🤖 Claude 完了: AIUsageManager
```

- 最初の完了から2分待ち、その間に続いた完了を1行にまとめます（`🤖 完了: Claude「A」・Codex「B」`）。時刻は最初の完了の時刻です。名前は、対応待ちの一覧に出している名前です。
- 同じセッション・スレッドは、30分に1回までです。
- `now_doing_ai_done_exclude` に書いたフォルダー（フルパス、`;` 区切り）と、その下で動いた作業は書きません。一覧に出す名前ではなく、作業フォルダーの場所で比べます（大文字小文字と、末尾の `\` の違いは同じとみなします）。
- 書く前に、日誌が直前10秒以内に変わっていたら（Obsidian で打っている最中かもしれないため）、10秒おきに待ち直します。5分たっても変わり続けていたら書きません。
- 日誌がないときや書けないときは書かず、通知もしません。書いたあとのスクリプトは実行しません。
- 書く直前の日誌の中身を `%LOCALAPPDATA%\AIUsageManager\ai-done-last.md` に1つだけ残します。

日誌の場所などは、アプリと同じフォルダーの `settings.ini` に書きます（`settings.ini` は Git に入りません）。`settings.ini` は UTF-8 で保存してください。ほかの文字コードのときは、日本語の場所を読めないうえ、トレイのメニューでテーマなどを変えても `settings.ini` を書き換えません（書き換えると日本語の行が壊れるため）。窓を開いたときに読み、書くときもその内容を使います（窓を開いたまま書き換えた分は、次に開いたときから使います）。

| キー | 中身 | 書かないとき |
|---|---|---|
| `now_doing_note` | 日誌のファイルの場所。`{ }` の中は日付の書式（.NET の日付の書式）で置き換えます。例: `C:\Notes\{yyyy}年_日誌\{yyyy-MM-dd} - 日誌.md` | 書けません |
| `now_doing_heading` | 日中ログの見出しの行（行全体が一致するもの） | `## 📝 日中ログ` |
| `now_doing_before` | 日中ログの終わりの目印。この文字で始まる行より後ろには書きません | 同じか上の階層の次の見出しが終わり（`## ` の見出しなら、次の `# ` か `## ` の行） |
| `now_doing_claudian` | `on` にすると、Ctrl+Enter で Claudian にも送ります | 送りません（Ctrl+Enter は Enter と同じ） |
| `now_doing_hotkey` | 窓を開くショートカットキー。Ctrl・Alt・Win のどれかを含め、`+` でつなぎます（Shift も使えます）。キーは A〜Z、0〜9、F1〜F24、Space。例: `Ctrl+Alt+N`。または2回押しの `DoubleCtrl`・`DoubleLeftCtrl`・`DoubleRightCtrl`・`DoubleShift`・`DoubleLeftShift`・`DoubleRightShift`・`DoubleAlt`・`DoubleLeftAlt`・`DoubleRightAlt` | ショートカットキーなし |
| `now_doing_button1`〜`9` | ボタン（`<名前>\|<動き>:<中身>`） | ボタンなし |
| `now_doing_after` | 書いたあとのスクリプトの命令 | 実行しません |
| `now_doing_list` | 一覧のスクリプトの命令 | 「まだのこと」を出しません |
| `now_doing_workdir` | スクリプトの作業フォルダー | アプリのフォルダー |
| `now_doing_ai_done` | `on` にすると、AI の完了を日中ログに書きます（トレイアプリ） | 書きません |
| `now_doing_ai_done_exclude` | AI の完了を書かない作業フォルダー（フルパス、`;` 区切り、その下も除く） | 除きません |

- 書く直前の日誌の中身を、`%LOCALAPPDATA%\AIUsageManager\now-doing-last.md` に1つだけ残します（次に書くときに置き換えます）。書き込みの途中で失敗したときは、これで元に戻せます。
- トレイアプリが動いていなくても使えます（2回押し・ショートカットキーと AI の完了は、トレイアプリが動いている間だけです）。「未接続」や「起動中」のときに押しても、トレイアプリは起動しません。
- アプリの場所が分からないときや起動できないときは、キーに「アプリの場所を設定」と出します。起動できたときは ✓ を出します。
- このキーには設定画面がなく、長押しにも同じ動作をします。
- 画面とほかのアプリの中身は読みません。読むのは、窓に入れた文字、日誌のファイル、貼り付けるときのクリップボードの文字、スクリプトの標準出力です。2回押しの設定のときだけ、トレイアプリが左右の Ctrl・Shift・Alt の押し離しと時刻を見ます（上の「2回押しで開く」）。アプリは通信しません（スクリプトがすることは、そのスクリプトによります）。

## トレイアプリが起動していないとき

- Stream Deckアプリが起動したとき（ふつうはWindowsのサインイン時）にトレイアプリが動いていなければ、プラグインがトレイアプリを1回だけ起動します。トレイアプリのウィンドウは開きません。その後にトレイアプリを終了した場合は、自動では起動し直しません。
  - 起動するのは、Stream Deckアプリの起動から1分以内にこのプラグインのキーが表示されたときだけです。キーを別のページやフォルダーに置いていて、後から表示した場合は起動しません。
  - プラグインの更新や、Stream Deckアプリを起動し直した直後も、同じように1回起動します。
- Stream Deckを使っていないときもサインイン時に起動させるには、トレイアプリの右クリック →「Windowsのサインイン時に起動」をオンにします。両方が同時に起動しようとしても、動くトレイアプリは1つだけです。
- トレイアプリを終了すると、最大で約7秒後に「未接続」になります。
- 「未接続」のキーを押すと、トレイアプリを起動します。起動を待つ間はすべてのキーに「起動中」と表示し、その間のキー操作は受け付けません。値が出るまで十数秒かかることがあり、最初は「未取得」と表示される場合があります。約10秒たってもトレイアプリが見つからなければ「未接続」に戻ります。Stream Deckアプリを終了しても、起動したトレイアプリは動き続けます。
- 起動するのは、トレイアプリが前回起動したときに記録した場所（`%LOCALAPPDATA%\AIUsageManager\app-location.json`）のアプリです。設定画面の「トレイアプリの場所」に `AIUsageManager.exe` までの絶対パスを入力した場合は、そちらを優先します。Stream Deckの起動時の自動起動でも同じです。
- 場所が分からないときは、キーに「アプリの場所を設定」と表示します。トレイアプリを一度手動で起動するか、設定画面で場所を入力してください。Stream Deckの起動時の自動起動では、この表示は出さずに「未接続」のままにします。

## 必要なもの

- Windows 10以降と、Stream Deck 7.6以降。
- **このプラグインと同じソース版からビルドしたAI Usage Manager**。v1.0.0や、Stream Deck連携を含まない旧ビルドでは「未接続」のままになります。使用枠の表示を変えた版（2026-11）とそれより前の版を組み合わせた場合も、2回続けて読めなかった後に「未接続」になります。障害情報に対応する前のトレイアプリでは、「AIの状況」キーは「未取得」のままです。
- ビルドする場合は Node.js（`node` コマンド）。プラグインの実行には、Stream Deckに同梱されている Node.js を使います。

## 導入

1. リポジトリのルートで、配布ファイルを作ります。

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\package-streamdeck.ps1
   ```

2. できた `dist\AIUsageManager-<版>-streamdeck.streamDeckPlugin`（例 `AIUsageManager-1.5.1-streamdeck.streamDeckPlugin`）をダブルクリックし、Stream Deckに追加します。

   Stream Deckは、すでに入っているものと同じ版番号のファイルを入れ直しても更新しません（ログには「AlreadyInstalled」と記録されます）。プラグインを更新するときは、`streamdeck/manifest.json` の `Version` を上げてから作り直すか、Stream Deckの設定 →「プラグイン」で一度アンインストールしてから入れてください。
3. 「AI Usage Manager」の一覧から、キーをボタンへ置きます。

## 「AI Limits」プラグインを使っている場合

第三者製の「AI Limits」プラグイン（`kr.co.postgresql.ai-limits`）と併用すると、トレイアプリでClaudeの使用量を取得できなくなることがあります。

- AI Limitsは、トレイアプリと同じClaude Codeのログインで、同じ取得先に約30秒ごとに問い合わせます。
- さらに、取得に一度失敗すると、待ち時間なしで問い合わせを繰り返すことがあります。その結果、取得制限（HTTP 429）がかかり続けます。
- 取得制限はアカウント単位でかかるため、トレイアプリの問い合わせも失敗します。

このプラグインに移る場合は、Stream Deckアプリの設定 →「プラグイン」でAI Limitsをアンインストールし、このプラグインのキーを置き直してください。AI Limitsのキーの設定は引き継げません。アンインストール後、取得制限が解けるまで時間がかかる場合があります。

## 削除

Stream Deckアプリの設定 →「プラグイン」でAI Usage Managerをアンインストールします。トレイアプリが記録した `app-location.json` は残ります。不要なら削除してください。
